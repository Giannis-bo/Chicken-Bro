# 榜单样本比较

先检查用户要求的累计范围，再发现榜单与样本；跨组先保证最小覆盖，再深入比较。榜单本身不等于原因分析；需要战斗归因时按需读取 wcl-analysis。

- 用户问高分玩家、热门配装或天赋趋势但没有给角色链接时，可用 `query_raiderio_rankings` 按专精和地区发现样本；`season=current` 从上游确认当前赛季。再按需用 `query_raiderio_characters` 批量查装备天赋，不要求用户提供工具能够自行发现的链接。未指定地区时可以先看世界榜并说明样本范围；用户指定国服或历史赛季时遵循其范围。

- 仅在累计样本不足 10 且确有必要时，用返回的页码/偏移继续抽样，区分榜单专精与角色当前专精。保留成功样本和失败数；装备快照时间不等同于打出分数的时间。依据已选择天赋、套装和可自由选择的宝石/附魔等解释配置；面板属性缺失时不反算或猜测百分比。排名和配置相关性不代替个人收益的因果证明。

玩家要求团本前N名时，先用 query_warcraftlogs_rankings 的目录核对团本、正式服/PTR、分区与难度，再按每个Boss、职业专精、指标和地区查询榜单。不得把网页403等同官方API不支持，不沿用前文未经核实的zone/encounter ID。全世界榜不传具体地区；明确保留榜单时间、范围与排名。只支持累计最多 10 名玩家；前100和全量遍历先拒绝，不调用工具。limit及分页均受累计预算约束，不要把返回数量当作已分析数量。

从真实排行的reportUrl继续读取报告，按角色名和服务器匹配actor，再核对施法/事件。已有明确分析目标时主动开始有证据的分析，不只给榜单或再次索取玩家链接。已获用户接受的有界研究中，列出实际分析的Boss、名次、样本数量与未覆盖部分，并给出具体观察；不能把少量抽样冒充全部前N的共性，不能把工具可用当成分析完成。历史错误范围应主动更正。

跨多个Boss或分组的研究，先检查范围不超过 3 组、10 名玩家及 3 场深度战斗，再列出覆盖清单；超限先拒绝原范围并提出缩小建议。第一轮先取得每组榜单并为每组至少一个匹配样本读取最小必要的整场统计及施法窗口，形成逐组有证据的观察；在这轮覆盖完成前，不把预算集中用于少数组的整场事件翻页或额外时间窗口。可独立的查询按现有有界批量工具并行，复用已有角色、报告和统计。完成覆盖后再在剩余预算内增加名次、窗口和比较深度；预算内仍无法覆盖的组必须逐项注明原因，仍不得将部分研究称为全部分析。该顺序不扩大工具权限、查询预算或超时。
