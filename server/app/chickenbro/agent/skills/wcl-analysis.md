# WCL 战斗分析

先定位报告、战斗、角色及时间窗，复用已有证据；优先整场汇总，再补能改变结论的窗口。按数据完整性区分统计观察与操作归因；需要机制解释时按需读取 mechanics。

- 资源溢出、治疗过量、技能次数与冷却空档是观测事实；判定操作失误或建议替换技能时，还要有当时需求和替代收益的依据。不能把溢出资源直接换算成少打几次技能、损失多少有效治疗或伤害。

- 治疗建议按相关时间窗核对目标和团队的缺血、持续或即将到来的承伤，以及资源、冷却、施法时间和目标可达性。团队平均血量或高过量率不能代替逐目标需求；当前满血也不能排除即将到来的治疗窗口。只补查会改变当前建议的证据，不为每个统计问题机械查询全场。

- 比较当前选择与可行替代：救治收益、伤害、回蓝、资源准备和后续技能衔接都可能影响选择。低压力时允许合理补伤害或保留资源；有急迫救治需求时优先及时治疗。不要形成“满资源必须消耗”“满血固定打某技能”或“溢出一定是错”的口诀；只有替代方案的时机和收益有依据时才确定建议换技能。

- 使用事件血量快照时核对与施法的时间差、覆盖目标及查询分页是否完整；单个目标满血、缺少事件或个人高过量不能证明全团无需治疗。对影响建议但尚未查询的信息，现有工具能取则先补查；取不到时说明这一个缺口，只给成立的统计或条件建议，不假称已核验，也不编造确定的收益提升。

- 用户质疑建议时重新检查原结论的证据和假设，明确修正超出证据的部分；不能只顺着追问改口。回答无需逐条展示这套检查，仅呈现影响当前结论的依据和可执行建议。

- 治疗对比先用 view=healing、指定fight/source取得整场有效/含过量总量及技能构成，再结合overview属性/天赋与casts。不同战斗按时长归一，技能父项与子项不重复加总。只补能区分剩余原因的施法、增益和团队承伤窗口；不遍历整场All事件或重复读轴。事件数和治疗命中次数不能直接当按键次数。

- WCL 已知且相互独立的事件类型或时间窗口，可使用 `query_warcraftlogs_batch` 一次并行查询最多三项；依赖上一页游标的分页仍顺序执行。保留各项 actor、fight、时间与完整性范围，不把重叠窗口重复计数。已返回的整场统计和玩家资料可复用，不因换事件页重新研究同一背景。

- WCL 的 cast 事件和施法次数是日志记录，不等于玩家主动按键、占用 GCD 或可避免的重复操作；自动触发、复制或其他次级效果也可能产生记录。将“次数偏多”升级为“少按某技能、减少刷新”的优先建议前，先核对当前版本的触发机制、天赋/装备及相关事件。未核实时保留频次差异和待核查项，不把该建议包装为已发现的操作问题；也不能仅因同毫秒共现就认定自动触发、合并事件或推断一次按键。多次规律同步同样不能证明宏绑定、按键习惯或两个独立主动动作；来源未核实时，不建议拆宏、独立按键或改变该联动。已有明确主动来源证据可据实分析，仍须核对需求和替代收益。只补查影响当前结论的证据，不机械扩大查询范围。

- 聚合施法统计只能支持频次，不能还原施放顺序。分析起手或技能衔接时，先核对同一报告、fight、actor 的事件类型与目标，将事件统一为战斗相对时间（timestamp - fight.startTime）并按时间排序；时间戳相同不能判定先后。最终回答涉及先后时，明确列出对应动作的相对时间；涉及目标变化时同时注明已核验的目标或 targetID，不能用未知目标身份补全叙述。窗口内共现不能证明先后或因果，不能把后发生的事件写成前置动作；未取得对应时间或目标证据时，只保留成立的频次或共现观察。

- 复杂复盘优先核验能改变主要建议的窗口，已有证据支持主要结论时整理回答。工具明确提示研究预算耗尽时停止新增查询，说明已核验范围和剩余缺口；不得把尚未核验的时间点、收益或错误归因补写成事实。

- 玩家只给角色名和服务器要求找日志时，主动使用 `query_warcraftlogs_character` 查询近期公开报告；从上下文取得地区，无法确定时才澄清，不要求先贴报告链接。在剩余研究预算内按返回分页查询必要时间段，再用 `query_warcraftlogs_report` 核对角色名、服务器及参战场次，不能仅凭同名选择角色或把重复上传当成不同战斗。区分角色不存在、没有近期公开记录、隐藏与接口不可用。

- WCL 报告请求失败（例如 blocked、unavailable）且没有返回可用报告事实时，请求中的报告链接不等于已验证引用。说明限流、权限或其他取证缺口时，写清未读取的范围；需要来源入口时使用本次已成功返回的榜单或报告链接。不得把失败请求中新出现的 report/fight/source 组合作为正文引用，也不得用它支持身份、施法或覆盖结论；成功批量成员的证据独立保留。不要根据失败链接猜测替代报告或参数。
