# WoW 小程序 UI 风格规范

> 本规范用于后续所有小程序 UI 设计、评审和实现。新增页面或重做模块前，先对照本文件；已有页面逐步收敛，不要求一次性重构。

## 设计基调

项目的主风格是 **移动端艾泽拉斯分析控制台**：黑曜石底、暗铁/深棕面板、魔兽金强调、真实游戏图标和高密度数据。它应当像玩家在手机上查看装备、天赋、日志和模拟证据的工具，而不是营销落地页、厚重页游皮肤或普通 SaaS 卡片墙。

视觉优先级如下：

- 先保证信息可扫读：职业、专精、来源、样本、状态、主要动作必须一眼能定位。
- 再提供 WoW 感：用金边、暗铁面板、职业/装备/天赋图标、状态条和层级数据表达游戏语义。
- 装饰必须克制：不要新增大面积插画、无意义渐变、光球、过厚阴影或占据首屏的氛围图。

## 色彩体系

新增样式应优先复用这些语义色，不要随手增加裸色值。

| 语义 | 推荐色值 | 用途 |
| --- | --- | --- |
| 页面底色 | `#060606`, `#0B0907` | 全局背景、滚动页底 |
| 普通面板 | `#101010`, `#151515` | section、卡片、列表项 |
| WoW 暗铁面板 | `#17120D`, `#21170F` | 需要更强游戏感的工具面板、WebSim 类视图 |
| 分割线 | `rgba(255,255,255,0.08)` | 默认边框、列表分割 |
| 金色主强调 | `#F8B700` | 主 CTA、当前选中、关键数值、来源重点 |
| 正文 | `#E1E2E5`, `#F1F1F1` | 主文本、标题 |
| 次级文案 | `#A7A7A7`, `#8E8E8E` | 描述、时间、来源补充 |
| Verified | `#58C98E` | 已验证、可执行、可提交 |
| Partial / Warning | `#F8B700`, `#F2A65A` | 部分可用、缺字段、需补齐 |
| Source reference | `#54C0FF`, `#5E8DFF` | 参考来源、非可执行证据 |
| Blocked / Error | `#FF6B64`, `#FF8C80` | 阻断、失败、不可提交 |
| Build / Sim 辅助紫 | `#8B3FF5` | 构筑/模拟的辅助强调，不作为全局主色 |

页面不得形成“每个 tab 一套主色”的状态。资讯、职业、PVE、模拟器可以有轻微模块强调色，但大面积背景、面板、边框和主 CTA 仍回到暗色 + 金色体系。

## 移动端密度

小程序优先节省垂直空间。默认目标是：首屏能看到当前页面的核心信息和至少一个关键动作。

- 页面横向 padding 默认 `20-24rpx`，复杂工具页最多 `28rpx`。
- section 间距默认 `16-20rpx`；普通卡片间距默认 `10-14rpx`。
- 普通 section padding 默认 `16-20rpx`；重要面板最多 `24rpx`。
- 新增卡片圆角默认 `10-12rpx`；底部 sheet 可用 `24-28rpx 24-28rpx 0 0`；不要继续扩大普通卡片圆角。
- 常规按钮高度 `56-64rpx`；主提交按钮最多 `72rpx`；只有固定底部主操作允许更高。
- hero 是紧凑信息头，不是大 banner。常规高度控制在 `180-240rpx`，标题 `34-40rpx`，描述最多 2 行。
- 长正文、日志报告、输入框可以纵向展开；筛选、状态、来源、动作优先压缩成行。

## 同排布局

按钮和文案能放到一排时，必须优先同排。

- section header 固定为左标题、右状态或动作：例如 `职业天梯` + `source_reference`，`装备模拟` + `16/16`。
- 卡片头部固定为左主信息、右状态/数值/短操作；右侧内容要短，不放整句解释。
- 筛选、picker、tab 使用单行工具条或横向滚动条；不要把每个选择项堆成独立大卡。
- 操作按钮优先一行 2-3 个：例如 `保存模板 / 导入社区 / 重置`。超过 3 个动作时移入 bottom sheet 或二级菜单。
- 按钮文案保持短动词：`保存`、`导入`、`重置`、`提交分析`、`查看详情`。长说明放在旁边的状态文案，不塞进按钮。
- 如果按钮文案会溢出，优先改短文案或改成全宽按钮；不要让按钮撑破卡片。

## 固定 Tab 与 App Shell

底部固定 tab 必须使用微信原生 `app.json` `tabBar`，不要在页面里伪造固定 tab、状态栏或手机 chrome。

- 每个 `tabBar.list` 项必须有 `iconPath` 和 `selectedIconPath`，图标使用本地 `assets/tabbar/` 下的运行时资源。
- 页面内容通过 `AppShell` / `PageFrame` 预留 tab-safe bottom floor，不单独写底部安全区补丁。
- 资讯频道这种页面内筛选 dock 可以使用 `ChannelDock`，但它不是全局底部 tab 的替代品。
- imagegen 或目标图素材不能直接裁成底部 tab 图标；固定 tab 图标必须是明确的运行时 UI asset。

## 组件规范

新增 UI 应优先复用或抽象以下组件语义：

- `AppShell + PageFrame`：新 UI 系统的默认页面外壳，统一背景、滚动、横向 gutter、section gap 和 tab-safe bottom floor。
- `page-shell + page-scroll + page-content`：仅作为旧页面历史结构保留；新接入 surface 不应继续扩展这套 page-private 几何。
- 紧凑 hero：kicker、title、desc、右侧状态或小数值，最多一个轻量渐变。
- section：标题行 + 内容区；不要把 section 再套成多层大卡。
- toolbar picker：左标签 + 右 picker/value，一行完成选择。
- segmented tabs：2-5 项一行展示；选中态用金色边框/底色，不用大面积填色。
- status badge：统一表达 verified、partial、source_reference、blocked、stale；同一状态跨页面颜色一致。
- game icon frame：装备、职业、专精、天赋优先用真实游戏图标；缺图标时用短文字 fallback，但不能伪装成真实资产。
- bottom sheet：用于装备候选、社区模板、保存弹窗等局部任务；sheet 内继续保持紧凑行和全宽主按钮。

## 数据可信 UI

数据可信度是产品核心，不能被装饰盖住。

- `verified` 表示已校验、可作为强结论或可执行输入。
- `partial` 表示部分可信或缺少字段，只能用于参考或继续补齐。
- `source_reference` 表示来源参考，不得表现成已验证事实。
- `blocked` 表示阻断，必须给出确定性原因和下一步。
- `stale` 表示过期或赛季漂移风险，不能继续输出强结论。

绿色只用于 verified / 可执行 / 可提交，不用于“可点击”这种普通交互提示。普通可点状态用边框、阴影或金色选中态表达。

## 文案规则

- 标题说对象，副文案说状态；不要用页面文案解释 UI 怎么用。
- 来源、时间窗口、样本量、状态尽量合并成一行 meta，例如 `Raider.IO · 2 weeks · verified`。
- 阻断态直接说缺什么，例如 `缺少 16 槽装备配置`，不要写泛化失败文案。
- AI / LLM 相关文案必须区分“证据事实”和“解释建议”，不能把推理包装成已验证结果。

## 智能分析聊天 UI

`pages/simulator/simulator` 当前首屏就是“炸鸡队长”聊天，而不是模块卡片 hub。新增或调整智能分析 UI 时保持以下约束：

- 消息区使用左右气泡：炸鸡队长在左，用户在右；长消息在气泡内换行，不撑破 scroll-view。
- 底部输入区固定在页面底部，包含 textarea、发送按钮和“新话题”入口；键盘弹起、长文本输入和发送中状态不得遮挡最后一条消息。
- 话题列表使用抽屉或独立列表页，不常驻挤压聊天主视图。
- 发送后必须显示“发送中 / 生成中 / 已完成 / 失败”等明确状态；后端 fallback 也要展示为有效回复，不能空白等待。
- 回答依据、fallback、scope refusal、缺证据和 blocked 状态可以作为紧凑证据面板展示，但不能比主聊天内容更抢占首屏。

## 新 UI 检查清单

提交任何小程序 UI 前，至少检查：

1. 首屏是否能看到核心信息和关键动作。
2. 页面是否仍属于暗色 + 金色 + 游戏图标的统一体系。
3. 是否新增了未登记色值；如新增，是否有明确语义。
4. section header、状态、来源、按钮是否能同排而没有被纵向堆叠。
5. 按钮高度、卡片 padding、hero 高度是否符合移动端密度规则。
6. 长标题、长装备名、长来源、长按钮文案是否会溢出或遮挡。
7. verified、partial、source_reference、blocked、stale 是否颜色和文案一致。
8. 展示型数据是否被错误表现成可执行或已验证数据。

## 现有页面收敛方向

现有页面不用一次性重写，但后续改动应逐步收敛：

- `app.wxss` 的通用 section、hero、card、badge、button 规则应成为默认入口。
- `websim/app.css` 中更强的暗铁/深棕/金边气质可作为 WoW 工具面板参考。
- `pages/builds/detail.*`、`pages/simulator/simc.*` 已有紧凑 action row 和 picker 行，应优先复用这种布局。
- `pages/simulator/simulator.*`、`pages/simulator/chickenbro.*`、`pages/simulator/chickenbro-chat.js` 是智能分析聊天形态的当前基准：左 / 右气泡、fixed composer、新话题和 topic drawer 优先于卡片式模块入口。
- `pages/news/news.*` 的大 banner 后续可逐步压缩，避免资讯首屏占用过高。
- `pages/pve/detail.*` 的 chart table 是移动端高密度数据展示参考，后续排行类模块优先复用这种表格转译方式。
