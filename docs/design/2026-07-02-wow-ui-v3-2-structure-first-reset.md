# WoW 小程序 UI v3.2 结构优先重启

## 背景

v3 和 v3.1 均不能作为实施目标。

失败原因：

- 先追视觉稿，导致布局基础没有先被验证。
- imagegen 整页壳带来不可控的顶部装饰、返回按钮冲突、文字发虚和间距混乱。
- 页面看起来像贴了素材，而不是由真实小程序组件组成。
- 评审焦点被材质和氛围带偏，核心问题（导航、安全区、文字盒、组件间距、首屏信息顺序）没有先过关。

## 当前判断

下一轮必须停止“先出高保真图”的流程。

v3.2 的目标不是马上好看，而是先把真实移动端 App 的骨架做对。只有结构通过 CR 后，才允许进入视觉增强。

## 设计顺序

1. 低保真结构线框
   - 只用黑、白、灰、少量状态色。
   - 不使用整张 imagegen 背景。
   - 不使用装饰边框。
   - 不使用大标题压信息。

2. 布局 CR
   - 返回按钮在安全区内，不能压顶部标题或装饰。
   - 页面标题清晰，不能发虚、不能浮在背景纹理上。
   - 首屏主路径可扫读：当前对象、能否模拟、为什么、下一步。
   - 文本盒有固定宽度、最大行数和省略策略。
   - 模块间距使用统一 scale，不凭感觉摆。
   - 底部 tab 使用真实小程序组件心智，不伪造状态栏或装饰导航。

3. 组件语义稿
   - object plate：当前职业 / 专精 / 英雄天赋 / 场景。
   - readiness slab：能否模拟、主阻断、主 action。
   - module dock：天赋、装备、SimC、队长四模块状态。
   - source ledger：资讯和证据列表。
   - context bridge：SimC / Chickenbro 从工作台承接上下文。
   - evidence drawer：资深玩家展开证据。

4. 视觉增强
   - 只在结构通过后添加材质。
   - imagegen 只生成可裁切的局部纹理、空态图或边缘材质。
   - 真实 WoW 图标只来自真实 asset chain。

## 禁止项

- 禁止再用整张 imagegen UI 壳作为目标稿。
- 禁止先画高保真再回头解释布局。
- 禁止让背景纹理穿过正文区域。
- 禁止返回按钮、标题、状态栏、顶部装饰互相压叠。
- 禁止为了题材感牺牲可读性。
- 禁止把 v3 或 v3.1 目标图作为 Phase 5 实施依据。

## 下一轮产物

先只产出 6 张低保真结构线框：

- 工作台首屏。
- 工作台证据展开。
- 资讯滚动列表。
- 职业专精 tab。
- SimC 承接态。
- Chickenbro 承接态。

每张线框必须带：

- 当前真实截图引用。
- 保留的信息列表。
- 布局区域编号。
- 安全区说明。
- 溢出处理说明。
- 为什么比当前小程序更容易扫读。

通过用户确认后，再进入高保真视觉稿。
