# WoW 小程序 UI v2.1 密度版设计规格

> 目的：把 v2 概念效果收敛为可落地的小程序 UI 规格。v2.1 保留暗色艾泽拉斯控制台气质，但优先级改为真实数据、真实图标、首屏密度和状态语义。

## Design Read

这是一个面向 C 端 WoW 玩家的移动端证据化构筑工具，不是 landing page、概念海报或后台 dashboard。视觉语言是暗色艾泽拉斯分析控制台，核心体验是“当前能否模拟，为什么，下一步去哪”。

## TasteSkill Dials

- `DESIGN_VARIANCE: 5/10`：允许暗铁材质、金边和强层级，但每页结构必须稳定复用。
- `MOTION_INTENSITY: 2/10`：只做点击反馈、状态切换、展开收起；不做滚动炫技和重动效。
- `VISUAL_DENSITY: 8/10`：首屏必须看到当前对象、证据状态、阻断原因、关键动作和下一块内容。

## 设计原则

1. 真实图标优先：职业、专精、天赋、装备只使用 `gameAsset.iconUrl`、`iconUrl`、Battle.net / WebSim read model 中的真实图标。缺图时使用中性文字 fallback，不使用 imagegen 伪造。
2. 状态色锁定：金色只用于主 CTA 和当前选中；绿色只用于 verified / 可执行 / 可提交；红色只用于 blocked；蓝色只用于 source_reference；黄色用于 partial / warning。
3. 首屏密度优先：hero 是紧凑信息头，不是大 banner。工作台首屏必须露出主结论、主 action、阻断摘要、四模块状态带和证据摘要入口。
4. 证据不藏深：来源、检查时间、阻断原因、缺失项至少有摘要行；展开区再给资深玩家完整细节。
5. 每页一个主动作：工作台补阻断，资讯看来源，职业进入当前工作台，SimC 校验组合，Chickenbro 追问证据。
6. 不输出无证据强结论：无完整 SimC-ready 天赋和装备前，不显示模拟数值、综合评分、S/A 级、提升优先级。
7. imagegen 只做材质底：暗铁、奥术线框、状态氛围可以来自 imagegen；真实对象和业务结论不能来自 imagegen。
8. 真实微信容器：落地实现不包含伪手机外壳、伪时间、伪胶囊或效果图标题。

## 页面规格

### 当前专精工作台

首屏结构：

- 紧凑页面头：`当前专精工作台` + 场景 / 证据状态短 badge。
- 当前对象条：真实专精图标或文字 fallback、职业、专精、英雄天赋、场景。
- 主结论 slab：聚合状态、主 blocker、主 action。
- 阻断摘要：最多 2 条，每条必须有“缺什么”和“去哪补”。
- 四模块状态带：天赋、装备、SimC、队长，展示真实状态，不用普通卡片墙。
- 证据摘要：来源、检查时间、状态，不展开也能知道可信边界。

文案示例：

- `缺装备，暂不能提交 SimC`
- `补齐装备`
- `天赋可读`
- `装备阻断`
- `SimC 待校验`
- `队长可解释证据`

### 资讯首页

首屏结构：

- 紧凑情报头：`版本情报` + 最近检查时间 / 来源状态。
- 来源摘要 rail：官方来源、可发布、待检查，用真实 payload 聚合。
- 重点列表：首屏至少露出 4 条；每条包含标题、来源、日期、状态、频道。
- 禁止硬编码 `4 条重点更新`、`2 条职业相关` 这类假精确数字，除非由 payload 计算。

### 职业 tab

首屏结构：

- 当前专精 mini workbench entry：进入当前工作台，而不是重复讲“从当前专精开始”。
- 当前账号状态 strip：天赋模板数、装备模板数、最近任务、当前聚合状态。
- 工作流入口：天赋、装备、SimC、队长，展示真实状态和短动作。
- 职业 / 专精选择保持紧凑 picker，不把选择项堆成大卡。

## v2.1 Pre-flight

- [ ] 首屏是否露出核心状态、主 action 和下一块内容。
- [ ] 是否无 `真实图标位`、伪状态栏、伪手机壳、效果图标签。
- [ ] 所有对象图标是否来自真实 URL 或中性 fallback。
- [ ] 所有数量、状态、日期、来源是否来自真实 payload 或明确为样例稿。
- [ ] 绿色是否只用于 verified / 可执行 / 可提交。
- [ ] 是否没有模拟数值、综合评分、S/A 级、提升优先级。
- [ ] 普通卡片圆角、按钮高度、section 间距是否符合 `docs/ui-style-guide.md`。
- [ ] 长职业名、长装备名、空态、加载态、错误态是否有落地规则。
