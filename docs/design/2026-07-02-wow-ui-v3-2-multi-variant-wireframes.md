# WoW 小程序 UI v3.2 多方向结构线框

## 状态

proposal。仅用于结构 CR, 不作为最终视觉稿或实施依据。

## 产出

本轮产出 3 个差异明显的低保真结构方向, 每个方向覆盖 6 个真实小程序场景, 共 18 张目标线框和 6 张现状对比板。

- 产物目录: `artifacts/ui-v3-2-structure/20260702-multi-variant/`
- manifest: `artifacts/ui-v3-2-structure/20260702-multi-variant/manifest.json`
- 总览图: `artifacts/ui-v3-2-structure/20260702-multi-variant/contact-sheet.png`

## 设计读法

这是移动端 C 端工具, 目标不是做营销页或整页氛围图, 而是让玩家在手机上快速判断:

- 当前对象是什么。
- 当前是否能继续模拟或分析。
- 为什么被阻断。
- 下一步去哪。
- 证据从哪里来。

本轮不使用 imagegen 生成整张 UI 壳。真实图标、职业资产和局部材质要等结构过关后再接入, 且只能来自真实素材链路或可裁切的局部生成素材。

## 三个方向

### A 行动驾驶舱

核心逻辑: 先告诉用户当前能不能继续, 再给最短下一步。

适合:

- 新手用户。
- 工作台首屏。
- 阻断态主路径。

风险:

- 证据细节可能下沉过多。
- 需要在视觉稿阶段补足题材感, 否则会偏工具感。

### B 证据账本

核心逻辑: 先把来源、字段、状态展开, 让每个结论都可追溯。

适合:

- 资深玩家。
- 证据展开区。
- SimC 提交前校验。

风险:

- 首屏行动感弱。
- 新手可能觉得字段太多, 需要默认折叠。

### C 任务栈

核心逻辑: 把工作台变成任务队列, 按阻断顺序推进。

适合:

- 跨页面流程。
- 职业 tab 到工作台的承接。
- 队长追问和 SimC handoff。

风险:

- 首屏信息密度偏低。
- 如果视觉层没有游戏化材质, 会像普通待办工具。

## 覆盖场景

- 工作台首屏。
- 工作台证据展开。
- 资讯滚动列表。
- 职业专精 tab。
- SimC 承接态。
- 炸鸡队长承接态。

每张对比板左侧都引用现状小程序截图, 右侧并排展示 A/B/C。目标是横向判断结构, 不是判断最终视觉。

## 自检结果

- 返回按钮位于安全区内。
- 标题不压背景图或装饰。
- 模块高度固定, 避免因为 hover、标签或长文案造成布局跳动。
- 长标题和长装备名采用 2 行封顶或行内省略。
- 强结论在输入不完整时只显示为隐藏边界, 不输出无来源数值、等级评价或收益判断。
- v3 和 v3.1 仍为失败探索证据, 不进入 Phase 5 实施。

## 当前推荐

不要三选一硬套。更合理的组合是:

- 工作台首屏使用 A 的行动驾驶舱。
- 证据展开使用 B 的证据账本。
- 职业 tab、SimC handoff、队长追问借 C 的任务栈。

结构通过后, 再进入视觉增强: 局部材质、真实 WoW 图标、职业天赋真实资产和小程序组件化实现。
