# WoW 小程序 UI v3.1 重 UI 资产修正版

## 状态

`rejected`

2026-07-02 用户继续否定 v3.1，主要问题是：

- 返回按钮和顶部装饰/文字层级冲突。
- 顶部文字发虚，视觉焦点不稳定。
- 间距混乱，整体仍不像可实施的小程序 App。
- 继续沿 imagegen 大图壳推进，只会让设计越做越差。

v3.1 只保留为失败样本和方法边界，不得作为 Phase 5 实施确认稿。

## 背景

2026-07-02 用户否定 v3 目标图，主要问题是：

- 布局乱，页面没有形成稳定舱位。
- 内部元素存在溢出和压边风险。
- 背景材质过杂，和文字、边框、状态色互相抢层级。
- 整体视觉弱于早前 v2.2 / v2.3 的重 UI 资产方向。

因此 v3.1 曾尝试不继续微调 v3，而是回收 v2.2 的重 UI 家具优点，同时保留 v3 的信息保真、真实图标和证据边界。但执行结果证明：整张 imagegen UI 壳会带来无法控制的层级、间距和导航冲突，不适合作为目标稿主路径。

## 设计读法

v3.1 是移动端 WoW 构筑与模拟伴侣 App，不是普通黑卡工具集合，也不是纯游戏皮肤。

目标体验：

- 第一眼有明确的 WoW 题材 App 气质。
- 信息被重 UI 框架托住，而不是浮在杂乱背景上。
- 首屏保留快速判断能力：当前专精、状态、阻断、下一步、四模块、模板数、证据摘要。
- 资深玩家能继续展开 coverage、checkedAt、catalogStatus、statSnapshot 和 blockers。

## v3.1 视觉原则

- 重 UI 壳只负责结构，不负责事实。
- 背景只在边缘和框架处显露，文字区必须有独立黑色安全底。
- 每个模块是固定舱位：固定宽高、固定行数、超长文本省略。
- 状态色只用于语义边框、左轨和状态文字，不铺满整块背景。
- 金色用于主路径和可操作动作，不到处做装饰。
- 蓝色只用于来源参考、证据、队长解释范围。
- 红色只用于阻断和限制，不用于氛围装饰。
- 不用整张 imagegen 图替代真实页面组件，实施时要把它拆成 WXSS 组件语言。

## 必须保留的 v3 规则

- 不生成假 WoW 职业、专精、天赋、装备图标。
- 不生成 Blizzard、Wowhead、Raider.IO、WCL、Battle.net 等来源 logo。
- 不制造 DPS、综合评分、S/A 级、提升优先级。
- `SimC` 模块 fallback 使用 `Sim`，不得使用容易误读为 S 级的单字母 `S`。
- 装备目录覆盖写作 `目录 190/206`，不得写成 `190/206 槽`。
- 队长只解释证据、阻断和下一步，不替代模拟评分。

## 实施注意

- 真实页面不要直接整张使用 `heavy-app-shell-mobile.jpg`。它是目标稿结构参考，不是最终生产背景。
- 实施时优先抽象组件：command plaque、object plate、readiness slab、module dock、source ledger、context bridge、bottom action/composer。
- 如果某个 imagegen 结构和真实内容尺寸冲突，以真实内容和可读性为准，删素材或换组件结构。
- 微信开发者工具截图必须再次验证移动端实际文本不会溢出。

## 后续方法修正

下一轮不得继续先生成整张 UI 壳或整页效果图。

新的顺序：

1. 用真实小程序尺寸做黑白/低保真结构线框，先解决导航、返回按钮、安全区、首屏信息顺序和间距。
2. 用真实组件盒模型表达 object plate、readiness slab、module dock、source ledger、context bridge，不使用整张 imagegen 背景承托页面。
3. 只在组件边缘或空态使用可裁切、可控、低透明的 imagegen 局部材质。
4. 每张目标图先过布局检查：返回按钮不压装饰，标题不模糊，文本不压边，行距和块距成体系，底部 tab 不被背景图伪造。
5. 结构稳定后再做视觉品味增强。
