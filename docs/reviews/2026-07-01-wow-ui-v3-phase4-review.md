# WoW 小程序 UI v3 Phase 4 评测与修正记录

> 本记录承接 `docs/design/2026-07-01-wow-ui-v3-information-inventory.md`、`docs/design/2026-07-01-wow-ui-v3-design-language.md` 和 `artifacts/ui-v3-comparison/20260701-phase3/manifest.json`。本轮目标是用 TasteSkill 和两个角色 subagent 审计 Phase 3 目标稿，并把有效意见反映回设计稿。

## Design Read

Reading this as: 面向 WoW C 端玩家的移动端构筑与模拟工作台 redesign，要求高信息密度、强题材识别、真实证据边界，倾向“艾泽拉斯分析控制台”而不是 landing page、后台 dashboard 或页游皮肤。

TasteSkill 本轮只作为反模板化审计器使用，不机械套 landing page 规则。采用的有效规则包括：

- 先审计现状信息资产，再重排视觉。
- 避免黑卡片堆叠、假精致边框和素材堆叠。
- 不用假图标、假来源、假数字或假评分制造高级感。
- 长文本、按钮、底部输入栏必须考虑移动端宽度和 safe-area。
- 视觉素材必须服务信息层级，不能遮挡或替代业务信息。

## Subagent 结论

### 新手魔兽玩家 + C 端产品视角

总体判断：方向正确，工作台、SimC 和 Chickenbro 已经从工具页向证据驱动 App 靠近；但资讯页和职业 tab 目标稿提升不够明显，真实 WoW 对象信号不足。

| 场景 | 评分 | 主要意见 |
| --- | ---: | --- |
| 工作台首屏 | 8.1 | 对象、场景、能否模拟、缺什么、去哪补更集中；但边框仍多，缺口文本截断过多 |
| 工作台证据展开 | 7.6 | 分组证据更清楚；仍偏技术 ledger，缺少“影响什么”的解释 |
| 资讯滚动列表 | 6.4 | 保留了信息，但像线框展示板，App 感不够强 |
| 职业专精 tab | 7.3 | 工作流方向正确；主 CTA 不应只写“进入” |
| SimC 承接态 | 8.0 | Context Bridge 有价值；选择控件不能被摘要化 |
| Chickenbro 承接态 | 7.8 | 证据教练定位正确；需要补回答来源、限制和运行状态映射 |

### 资深魔兽玩家 + 前端实现视角

总体判断：证据边界稳，但不能直接进入实现。目标图基本没有制造 DPS、综合评分、S/A 级、提升优先级，但有几个字段和控件表达会造成误读。

| 场景 | 评分 | 主要意见 |
| --- | ---: | --- |
| 工作台首屏 | 7.5 | `S` 容易被读成 S 级，`190/206 槽` 不符合 WoW 装备槽位理解 |
| 工作台证据展开 | 8.0 | 最接近资深玩家需要的证据账本；长缺口需要展开策略 |
| 资讯滚动列表 | 7.0 | Source ledger 方向清楚；App 内不能出现设计说明文案 |
| 职业专精 tab | 6.5 | 不能过度承诺 WCL 和高端玩家数据能力 |
| SimC 承接态 | 7.0 | 需要区分公共目录可用和个人模板可提交 |
| Chickenbro 承接态 | 8.0 | 定位稳；需要映射 answerSource、limitations、evidenceRefs，底部输入需 safe-area |

## 已采纳修正

本轮已直接反映到 `artifacts/ui-v3-comparison/20260701-phase3/` 的目标稿和 manifest。

| 问题 | 修正 |
| --- | --- |
| SimC 节点单字 `S` 容易被误读成 S 级 | 工作台首屏目标稿改为 `Sim` 中性标记，manifest 记录该修正 |
| `装备 190/206 槽` 字段不真实 | 改为 `目录 190/206`、`目录覆盖`、`已装备缺口`，并更新设计语言文档 |
| 公共目录和个人模板混淆 | 工作台和 SimC 文案明确“公共天赋可编码，但个人模板 0” |
| SimC 控件被摘要化 | SimC 目标稿恢复职业、种族、天赋模板、装备模板的可操作选择区 |
| 资讯页含设计说明 | 移除“频道 / 日期 / 标题...”这类说明文案，改成来源状态摘要 |
| 职业 tab 过度承诺 WCL/高端玩家 | 改为围绕当前专精、模板和模拟任务的证据校验表达 |
| 工作台入口 CTA 泛化 | blocked 态主 CTA 改为 `补装备` |
| Chickenbro 暴露工程字段风险 | 回答依据改为用户可理解的来源类型、证据引用、解释范围、限制、主要缺口 |

## 暂不采纳但保留风险

- 资讯滚动列表仍不是视觉最强场景。当前修正目标是先守住来源边界和列表可读性，真正的资讯首页首屏还需要在实施阶段结合真实频道和来源数做完整组件。
- 目标稿仍使用 PIL 静态设计板，不能证明微信小程序真实滚动、safe-area、长文本换行和图片性能。该风险必须留到 Phase 6 用微信开发者工具截图验证。
- 职业/专精真实图标目前在设计板中复用了真实截图里的冰霜图标作为观测参考。生产实现仍必须来自 `gameAsset.iconUrl`、接口 iconUrl 或受控真实资产索引，不能从设计板裁图。

## 后续实施约束

- 不把 `catalogCoverage`、`equippedSlots`、`missingSlots` 混成一个“槽位”指标。
- 不在没有完整 SimC-ready 天赋和装备模板前显示 DPS、综合评分、S/A 级或提升优先级。
- `source_reference`、`partial`、`blocked`、`verified` 必须跨工作台、SimC、Chickenbro 保持同一语义。
- 长缺口文本默认截断，必须给证据展开路径。
- imagegen 材质只能做背景、轨道、面板和空态，不承载真实 WoW 对象或业务结论。
- 底部输入栏、固定 action bar 必须处理微信 safe-area 和键盘遮挡。

## 修正后判断

Phase 4 后，v3 目标稿仍不是最终实施稿，但已经从“漂亮黑金稿”进一步收敛成可信的 WoW 构筑工作台设计输入。下一步应让用户确认修正版前后对比，再进入 Phase 5 实施。
