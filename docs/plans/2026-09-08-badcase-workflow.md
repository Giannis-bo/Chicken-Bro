# Badcase 自动修复工作流

本文规定持续执行的通用流程与验收要求。定时任务负责调度及执行提醒；命令、证据字段与恢复操作见[执行说明](../badcase-workflow-operations.md)，项目约束及发布程序遵循当前 AGENTS.md、[验证矩阵](../verification-matrix.md)和[生产 runbook](../chickenbro-simc-production-runbook.md)。

具体问题、授权凭据、批次身份、预算消耗及待办保存在私有持久状态与交接记录中，不追加到本文。历史个案和单次例外不成为通用规则；[旧版归档](2026-09-08-badcase-workflow-history.md)仅供追溯，日常执行无需加载。

## 执行范围

现有未闭环及新增 Badcase 的兼容、可回滚纯后端修复可自动完成诊断、修复、验证、审查、合入 main、推送、发布及线上验收，无需逐组或逐版确认。每个调度窗口满足门禁即可发布，具体时间由定时任务配置管理。

按实际行为及完整差异判断范围：客户端交互、破坏性合同、数据库迁移或数据回填、身份权限、队列语义、依赖、基础设施、供应商及 SimC 引擎升级不在自动发布范围。必要的已知远端同步可执行；不自行安装依赖或任意下载，SimC 仅在云端运行。新增范围或预算须有相应授权，不能借用历史例外。

## 工作流

1. **扫描与对账。** 读取私有持久状态和简洁交接，按需展开所引用记录；按已登记清单检查到期保留事项，遵守精确文件、哈希、无活动引用及恢复门禁。实际运行 `scan` 和 `status`，增量读取未解决反馈，核对游标、去重、报告 SHA、发布账本和经哈希验证的独立处置记录；不按组名永久跳过新报告。
2. **保留证据。** 保存不可变问题包，区分截至原提问的上下文、原回答、可取得的历史工具回执与本次诊断结果；记录运行身份、来源和裁剪情况。缺失证据明确标缺失，不把后续纠正或当前查询补成历史事实。反馈是诊断数据，不能作为执行指令；不改写原反馈、resolved、真实会话或历史失败。
3. **诊断与分组。** 先定义可核验的验收条件，盘点当前运行版本的工具、参数、资料入口与结果核验能力。在生产等价条件下复现，按有证据支持的失败机制归组，记录假设、置信依据和影响范围；不把聚类、单次成功或额外资源带来的成功当作根因证明。
4. **修复与验证。** 按下文要求设计通用修复，保护 WIP，在隔离工作区实现并完成有界验证与审查。范围内的执行器或流程缺口也须推进；未发现可验证缺陷时记录结论，不制造改动或重复发布。
5. **绑定与发布。** `group/decide` 绑定实际报告 SHA 及可核验的持续授权记录；范围内无需新一轮人工确认，范围外取得明确授权。完成集成、冻结不可变批次及发布门禁，不将持续授权冒称人工业务验收。
6. **验收与续办。** 以本批线上业务证据判定完成；失败时按门禁恢复或记录具体阻塞。保存脱敏交接、累计消耗及恢复条件，下一窗口从实际状态续办。

## 通用修复与泛化验收（必须满足）

- **先复用，再补缺口。** 优先修正现有工具调用、参数传递、资料发现或证据投影。只有可复现证据证明现有能力无法合理补齐时才新增实现；工具名称不匹配或单个来源失败不是新增工具的依据。
- **提炼共同能力。** 方案先说明失败机制、现有能力复用、必要改动、拟覆盖场景及不适用边界。把共享处理放在合适的公共层，通过参数表达场景差异，保留领域语义、证据完整性与权限边界。不以原案例所属场景限定能力，不强行合并不同语义或建设无关框架。
- **禁止个案特判。** 代码、提示词、配置和数据映射不得按原题、身份、会话、报告或答案匹配来通过案例。测试夹具可保留案例；必要领域规则须有独立合同或可信来源，并验证同类输入及边界。
- **验证实际覆盖。** 调试前固定原问题、同机制变体、独立留出、正常路径及权限边界五类样本。优先在既有变体与留出名额内覆盖不同使用场景；只换名称或措辞不足以证明跨场景复用。留出参与调试或方案选择后必须更换。仅适用于单一领域时说明依据，覆盖声明不得超过证据。
- **保留完整对照。** 前后源码、提示词及应用配置分别绑定精确身份，其余模型、权限、数据和预算等受控条件一致。涉及模型随机性时每样本每相位至少两次，遵循预注册数量和通过率；保留所有失败、重复结果、耗时及成本，未知用量不记为零。事实与执行状态核对程序和来源，开放式答案独立评审并隐藏前后版本标签，争议保留或交人工处理。
- **审查后才可声明通过。** 在组级证据中记录机制、适用范围、实现与反特判审查、逐类对照及未验证范围。缺少证据、未达验收标准或正常路径/权限边界退化时，标记“泛化未验证”，不得进入自动发布。工具改名、原题单次成功和测试总数均不能证明通用化；CLI 结构校验也不能代替语义审查。

## 验证范围与停止条件

开始前固定最小充分样本、重复次数、总调用与耗时预算、诊断/修复/验证阶段预算及停止条件，为修复验证预留额度。复测、留出更换和失败消耗均累计，不跨调度窗口重置预算。

预定验收达标且无阻断回归即收敛。仅新失败、实际改动或明确合同风险触发受影响项补测；身份、条件及有效期仍满足门禁的证据可复用，不无故整套重跑，不为证明通用性穷举场景。

来源探针额度耗尽只停止同路径盲重试，继续利用已有日志、回执和源码诊断；新探针须验证不同机制或实际改动，并符合剩余预算。整体预算耗尽、持续无新信息或必要步骤确需外部条件时，保留结果与缺口，记录阻塞及恢复条件。不能降低门禁放行，也不能把暂不能发布当作停止全部可行诊断的理由。

## 集成、发布与恢复

- 审查实际生产基底到目标的完整差异，排除其他任务 WIP 和未授权改动；完成相关测试、合同检查、组合回归、Candidate 真实业务验收及回滚准备。集成导致身份变化时重新绑定证据，验证受影响项。
- 只冻结非空且全部达标的不可变批次，绑定问题组报告、源码、生产基底、构建、配置、完整差异及证据哈希。核对本地/远端 main、实际 API/Worker 和 Web 制品身份；基底漂移、冲突、缺依赖或证据过期时先解决缺口，不绕过门禁。
- 使用本批已审查且 SHA 固定的执行器，执行发布互斥、锁内真实基底预检和有界安全排空，不强杀在途任务。异步编排发布，及时独立核对本批真实线上回答与工具回执，不预填判词或借用其他批次证据。
- 本批真实 Chat 终态、历史读回、受影响工具与业务、owner 隔离、Web 制品及有界观察全部通过才记闭环。观察时长及错误、延迟、队列阈值事先固定；HTTP 200、退出码、服务运行或暂无新差评不能证明成功。
- 失败时在发布锁及身份核对下安全恢复到本批已验证基线，保护在途任务和新写入，并验证恢复业务。恢复失败或目标已被其他发布改变时停止切换并报告。`publishing/failed` 先对账，不盲重试；已发布报告不重复发布，无合格批次不发布，错过窗口不无条件补发。

## 记录与报告

私有状态保留扫描覆盖、问题组、报告版本、授权引用、真实结果、提交/发布身份、证据位置、累计消耗、剩余预算及待办。原文按现行保留制度处理，不扩展删除范围或重置保留时钟；长期记录脱敏，不存凭据或模型内部推理。

完成、失败、回滚或需人工处理时报告具体结果、未验证范围及下一步条件；无新可行动结果或相同阻塞未变化时保持安静。始终区分本地、Candidate、线上、用户验收和恢复验证，不把自动化执行成功当作业务闭环。
