# 鸡哥研究质量：首轮实施

状态：`正在推进`。2026-09-06 用户已确认诊断方案并授权落地。以此计划作为本轮唯一执行记录，不替代 Harness。

## 场景与验收

用户只问“IO 上高分增强萨为什么暴击高”，没有给角色链接。鸡哥应自主确定赛季、发现相关样本、读取装备天赋、核对机制并解释原因。资料缺失只限制相应结论，不把可以自行完成的角色发现交回用户。回答仍精炼，不预置暴击结论或强制所有问题执行固定流程。

首轮保留原生 `gpt-6-astra/high`、现有独立 Mini/Web 身份和 Chat/SimC owner。只完善 Chat 内部只读查询工具；不新增产品页面、数据库、常驻服务或依赖，不运行本地 SimC。资料缓存与跨轮证据持久化列入后续，不冒充本轮完成。

## 实施步骤

1. **Raider.IO 分析查询**：新增 `server/app/chickenbro/raiderio_research.py`，通过既有 HTTP adapter 读取赛季、专精排行榜、单人和批量角色。固定 provider 主机、合法 class/spec、分页和批量上限；公开角色来源保留宝石/附魔说明、套装、已选择天赋、资料时间；不改变 SimC snapshot。对网络失败、空数据、部分批量失败输出真实状态及来源，不输出密钥。新增 fixture 回归，先失败再实现。
2. **网页有效性**：改 `server/chickenbro_public_web_research.py`，过滤导航/脚本/注释，优先正文，明确识别 JS 空壳和挑战页；有界正文片段支持定位续读和截断元数据。有效短正文不误拒。保持 HTTPS、公网地址和大小/时间限制，不把无内容标成有效证据。新增离线测试。
3. **接入和规则**：修改 `source_gateway.py`、内部 route 与 `chickenbro_native_mcp.py`，暴露排行榜/批量工具并传递经过校验的参数；单人查询提供分析投影，保留已有 capability 与 WCL 合同。规则取消“两次检索即停止”，改为按需要补证据、避免重复失败、保留请求总预算。记录脱敏工具状态、耗时、参数摘要与结果范围；不记录凭据/隐藏思考。
4. **评测与审查**：固定原题及变体、简单问题、缺数据/边界题，保存可复用评测输入和人工评分标准；检查样本事实、机制证据、适用范围、是否无谓追问、耗时。独立源代码审查后运行相关 backend/control 检查，全部新增测试纳入标准入口。
5. **测试发布**：先打包明确 commit 的受影响后端/工具文件至隔离云目录，使用已安装 runtime 跑测试及真实 API/原生模型调用。核对测试服务身份和变更前 SHA，备份后按精确文件更新测试后端及专用 MCP 路径；保留现有 Web/数据库和回滚。真实测试 Chat 原题通过后提供测试体验，用户验收前不合入 main、不清理任务分支。

## 具体回归

- 当前赛季由 upstream 返回；历史赛季显式指定；排行榜分页不中断且不把其他专精当样本。
- 批量最多 10 人、并发最多 3；部分失败仍保留成功证据，空批量/非法 URL/重定向私网/无效参数拒绝。
- Chat 角色投影包含 gem/enchant 名称和套装标识，天赋只保留选中项；原 SimC 源测试不变。
- JS 空壳、验证码、纯导航无有效事实；长导航后的正文可读；段落续读位置明确。
- MCP 参数经 capability gateway 全链路传达，过期/撤销能力无效，WCL 分页不回归。
- 原题不注入角色、赛季、过度充能答案；完整回答必须基于实际证据，不能仅凭状态码或关键词自动判合格。
