# 职业专精内嵌装备模拟设计

> 状态：已确认方向。2026-06-17 当前约束是不新增小程序页，直接升级职业专精详情里的“装备获取”模块。

## 目标

- 将 `pages/builds/detail` 中现有“装备获取”模块改为“装备模拟”。
- 在当前职业/专精上下文内展示满级穿戴属性、装备可信状态和 SimC-ready 状态。
- 支持按装备部位查看当前装备、选择替换候选、刷新属性差异。
- 视觉上适配小程序移动端，不做桌面式大表格，也不增加新的顶层入口。

## 非目标

- 不新增独立装备模拟器页面。
- 不在小程序端自行计算复杂属性。
- 不把展示型装备、来源参考或字段不完整的候选装备伪装成 verified 属性。
- Blizzard Game Data API 真实对账、外部日志站刷新和网络数据写入仍按凭据与审批节奏推进。

## 页面结构

模块标题从“装备获取”改为“装备模拟”。模块内部分三层：

1. 装备摘要：显示当前装等、满级状态、装备完整度、属性可信状态、SimC-ready 状态。
2. 满级属性快照：显示主属性、耐力、副属性、武器 DPS、护甲和关键派生值；只有后端返回 `statStatus=verified` 时才标为可信。
3. 装备槽位：用小屏友好的槽位网格或紧凑列表展示头、项链、肩、披风、胸、护腕、手、腰、腿、脚、戒指 1/2、饰品 1/2、主手、副手。

点击槽位后在当前详情页打开底部面板，展示当前装备、可替换候选、来源、缺失字段、SimC-ready 状态和替换后的属性差异。

## 数据契约

后端为模块提供权威装备状态，小程序只负责展示和交互：

- `equippedSet`：当前穿戴装备实例，按 canonical slot 组织。
- `slotReadiness`：每个槽位是否合法、是否缺字段、是否可用于 SimC。
- `statSnapshot`：满级属性快照，包含 `verified` / `partial` / `blocked` 状态。
- `replacementCandidates`：按槽位返回候选装备，包含来源、装等、图标、中文名、缺失字段和替换 delta。
- `gearSchemaRevision`、`itemMetadataRevision`、`checkedAt`：用于后续健康哨兵和数据漂移追踪。

装备实例必须至少表达 `slot`、`itemId`、`ilevel`、`bonusIds`、`gems`、`enchants`、`craftedStats`、`sockets`、`sourceRefs`、`metadataStatus`、`simcReady` 和 `statStatus`。

## 正确性规则

- 满级基础状态、装备属性、装备合法性和 SimC-ready 判断都由后端返回。
- 小程序不得根据装备文本、图标或来源说明推断属性。
- 缺少 ilvl、bonus、宝石、附魔、制造属性、插槽或职业可用性信息时，属性快照只能显示 `partial` 或 `blocked`。
- 戒指、饰品、主副手、双手武器、唯一装备、护甲类型和武器类型都必须进入后端校验。
- 用户可见文案要说清楚阻断原因，例如“缺少 bonusIds，无法确认满级属性”或“该专精不能使用此武器类型”。

## 实施阶段

1. 契约层：扩展现有装备 payload，新增 `equippedSet`、`slotReadiness`、`statSnapshot` 和 `replacementCandidates`，补后端测试。
2. 小程序模块：把“装备获取”改名为“装备模拟”，实现摘要、属性快照和槽位展示，保留现有来源信息作为详情。
3. 替换交互：实现槽位底部面板、候选装备筛选和替换后的状态刷新。
4. 可信状态：接入 verified/partial/blocked 展示，阻断伪正确属性和不可执行 SimC。
5. 移动端 QA：覆盖窄屏、长装备名、双戒指/双饰品、缺图标、blocked 状态和底部面板滚动。

## 验收标准

- 当前职业专精详情页中不出现新的装备模拟独立入口。
- “装备获取”文案已升级为“装备模拟”。
- 全职业专精都能看到装备槽位状态，即使数据不完整也有明确 blocked/partial 原因。
- verified 状态下能展示满级穿戴属性；非 verified 状态不会使用“正确”“已验证”等表达。
- 每个部位都能打开替换面板，并且替换不会破坏现有 SimC 输入契约。
- 小程序移动端截图中，属性面板、槽位和底部面板没有文字溢出或控件重叠。
