# 运营后台实施计划

用户已确认首版范围并授权推进、发布。设计依据：本任务中确认的总览、用户趋势、Chat、SimC 四模块及唯一 QQ 管理员。

**目标**：现有 Web `/admin` 提供北京时间运营统计，只允许经用户核验的 QQ 内部账号读取。
**架构**：Web → typed admin client/domain → admin route → analytics application → PostgreSQL read-only repository；沿用 HttpOnly QQ session。
**约束**：不新增依赖；不改用户业务数据；不运行本地 SimC；不接回旧管理后台。单个 `WOW_ADMIN_USER_ID` 由运维配置，空值拒绝所有访问。仅真实 QQ 身份可成为管理员，禁止测试账号。公开 access 接口只返回当前用户自己的账号核验标识及权限，不返回管理员身份。核验完成前不绑定。

- [x] 后端：测试未登录、普通用户、Bearer、空配置、伪造 owner、测试账号、已撤销会话；实现管理员审计、日期范围校验（最多 366 天）、数据库只读 repeatable-read 事务及超时。
- [x] 聚合：仅当前 AppID QQ owners、排除固定测试账号；按提问/任务创建日期建立 cohort，成功率=成功/(成功+失败)，无分母为 null；反馈率=有反馈/成功回复，解决率=已解决/有反馈；耗时只包含完成且时间有效记录；SimC 成功需正指标和 provenance。按日补零；区间活跃用户去重，不能相加 DAU。
- [x] 前端：`/admin` 路由，独立响应式页面；今天/7/30 天及自定义日期；趋势、状态、耗时和专精表；加载/拒绝/错误/空态，不显示 fallback 为真实零值；QQ 登录后恢复后台路径。
- [ ] 验证：Python 权限和聚合用例、云端隔离 PostgreSQL fixture、typed contracts/UI tests、typecheck/lint/H5 构建；浏览器查看实际页面。已有 QQ/CSRF/Chat/SimC 相关回归。
- [ ] 发布：精确后端与 Web 文件清单，独立 Candidate 验证与生产空闲门禁；API/Worker 同版切换，保留旧代码/Web/drop-in 恢复；绑定经用户确认的真实浏览器内部账号，验证本人 200 / 第二账号 403 / 无会话 401 与统计 SQL 对账。记录 source/ref/runtime/Web 身份、未验证项。
