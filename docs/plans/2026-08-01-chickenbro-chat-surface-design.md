## 用户目标与完成体验

玩家进入“队长”时，不应先理解证据面板、工作台上下文、建议库或内部分析模式。他只需：继续当前对话、开始新话题，或查看此前的对话存档。

完成时，`pages/simulator/simulator` 是炸鸡队长的聊天 Tab 根页：

```text
对话存档                 炸鸡队长                 + 新话题

                 完整、按时间滚动的会话

问炸鸡队长…                                              发送

资讯                    专精                    队长                    我的
```

深色表面和低饱和金色保留产品身份；页面不再由叠层描边、状态卡或装饰框组织。金色只标识当前 Tab 和关键动作。底部四项产品导航继续作为全局导航，不计入队长首页的功能集合。

## 第一阶段范围

### 聊天根页

- “队长”Tab 直接进入聊天，不再渲染智能分析看板、工作台上下文、预置问题、证据货架或固定状态区。
- 首次或新话题的空状态只显示一条简短、应用自有的欢迎语和输入框；不伪造历史、示例问题、玩家身份或资料完整度。
- 已选会话显示其完整、按时间排序的真实消息；不再限制为最近两轮。
- 发送时仅在当前会话流内显示等待态。传输或后端失败时保留真实用户消息，并在原位置提供同一会话、同一内容的重试；绝不合成队长回答。
- 新话题清空本地会话选择和草稿，但不删除服务端历史；首次真正发送时才创建会话，避免空白存档。

### 对话存档

- 顶部“对话存档”进入独立列表页，不压缩聊天页宽度。
- 列表按 `updatedAt` 倒序显示真实标题和时间；仅支持打开会话。本阶段没有搜索、重命名、删除或批量管理。
- 选中后加载同一 owner 的完整会话，并返回聊天根页。
- 访客会话以当前 `guestId` 为 owner；认证会话以当前认证用户为 owner。列表、详情和任何后续写入都不得跨 owner 可见。

### 回答内的受控能力

普通版本问答、资料查询、Raider.IO、WCL 和 SimC 仍遵守 2026-07-24 后端设计的受控 Tool / Worker 分层。它们不再各占首页区域：只有后端在一条真实队长回答中返回相应数据时，页面才显示该回答下的紧凑依据、限制、选择或任务附件。

所有来源、数字、任务和证据继续由后端事实层决定。零条返回证据时不显示来源附件；`partial`、`stale`、`blocked`、超时或模型降级不得被前端提升为已验证结论。

## 明确不做

- 不自动读取、传递或显示构筑页的职业、专精、场景、模板或其他工作台上下文。每轮请求只使用用户实际输入、当前会话历史，以及用户明确要求后获得授权的 Tool 结果。
- 不在本阶段把 `query_raiderio`、WCL 深度分析或受控 SimC 对比伪装成已完成能力；它们按原后端设计的阶段 1、2、3 分别实现和验证。
- 不增加任意 URL 抓取、模型直连数据库/API/密钥、自动大规模 SimC 搜索、未经授权的社区采集，或将单个来源的结果说成全局 BiS。
- 不改变既有 SimC 提交、装备模拟、任务详情或构筑入口的业务行为。

## 数据与接口合同

现有 `POST /api/chickenbro/messages` 和“按 id 读取会话”接口继续是单条会话的真值入口。本阶段新增受 owner 约束的会话摘要列表接口，并在 typed API client 中建立对应的严格响应校验：

```text
GET /api/chickenbro/sessions?limit=<1..50>&cursor=<opaque>
  -> sessions[] { sessionId, title, productPhase, createdAt, updatedAt }
     nextCursor | null

GET /api/chickenbro/sessions?id=<sessionId>
  -> session + messages[]
```

认证 owner 从 bearer token 注入；访客列表仅可在明确 `guest=1` 且当前 `guestId` 合法时查询。错误、缺失 owner、格式非法的 cursor 或 session id 均 fail closed。标题只能来自已经持久化的会话标题，时间只能来自后端字段。页面不从消息内容、设备时间或本地缓存猜测列表事实。

UI 的会话状态分为：`empty`、`loading`、`ready`、`sending`、`error`。所有状态保留聊天壳和输入区；归档加载失败不能清除当前已加载会话，发送失败不能制造 assistant turn。

## 与后端总架构的衔接

本阶段保持模块化单体边界：Taro 聊天页只调用 typed client；`wow-backend` 负责身份、会话、消息、Tool 调度、事实校验和公开 payload；PostgreSQL 是会话及用户资产的唯一运行时持久层。WCL / SimC 重分析在其后续阶段通过 PostgreSQL 任务和通用 Worker 执行，并将结构化结果回写到原话题。

聊天页不暴露 Tool 名称、参数表、原始 SimC、完整日志、令牌、内部 blocker 或模型内部推理。队长的表达仍保持“先结论、再 2–4 项依据、说明版本/来源/不确定性、给下一步”的既定顺序。

## 验收、风险与回滚

### 用户可见验收

- 玩家进入队长 Tab 后只看见对话、新话题和存档入口，不需要选择分析模式。
- 新话题不会删除存档；从存档打开后能看到该 owner 的完整真实会话。
- 回答中的依据、限制、任务进度仅来自同一后端响应，且错误路径不制造结论。
- 正式服与 PTR/Beta、WCL、Raider.IO、SimC 的现有证据与授权边界不因 UI 收敛而放宽。

### 自动化与候选验证

- 后端：会话列表排序、分页、认证/访客 owner 隔离、非法参数拒绝、详情隔离；既有消息/证据/降级测试不回归。
- typed client：拒绝字段缺失、角色错误、非法时间或 cursor 的响应。
- Taro：根页不再引用旧看板 owners；归档打开、切换、新话题、完整会话、发送和重试具备模型/页面合同测试。
- 最终运行改动按 Harness 的 backend + frontend 风险面进行候选部署 smoke；队长聊天、存档读取、访客隔离和真实微信关键路径分别记录证据。WCL/Raider.IO/SimC 后续阶段各自建立 release packet，不借用本阶段结果。

### 回滚

该切片只改队长聊天表面与会话读取能力。候选 smoke 或 owner/证据合同失败时，回滚任务分支即可恢复既有已发布页面；不触发数据迁移、异步同步、来源抓取或 SimC/WCL 执行。新增列表接口异常时必须失败并保留当前会话，不得降级为跨 owner、本地伪造或未隔离历史。

## 实施拆分

1. 冻结此需求合同，更新当前 UI 控制面和任务 release requirement；为会话列表、完整会话读取和极简交互建立先失败的合同测试。
2. 实现后端 owner 隔离的会话列表与 typed client；保持既有消息端点、Evidence Ledger 和 PostgreSQL-only 边界。
3. 用共享聊天壳替换队长 Tab 看板，实现存档页和完整消息流；淘汰该路径上被取代的固定区域合同。
4. 完成定向测试、UI 架构审计、候选部署与真实微信验收；以单独的 task-scoped release packet 收口。

Raider.IO、SimC 对比和 WCL 深度分析在上述聊天表面稳定后，沿 2026-07-24 方案独立推进，不把未验证 Tool 混进本阶段验收。
