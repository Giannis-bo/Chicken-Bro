# 鸡哥截图提问设计与实施

状态：正在推进；授权：2026-09-09 独立任务明确授权设计、实现和验证，不含生产发布或人工验收。

## 场景与合同

玩家在 Mini 或 Web 选择最多三张 PNG/JPEG（单张原始与规范化后均不超过 5 MiB，最大边长 8192，像素不超过 2000 万），看到预览并可移除。上传独立于发送；失败可重试，上传未完成不能发送。允许纯图或文字加图，发送失败保留草稿。服务端认证读取图片，历史只返回图片 ID/类型/宽高，双端按需读取；不公开图片 URL，不让客户端指定 owner。

POST /api/v2/chat/images：{dataUrl}，Idempotency-Key 必填，返回 {id,mimeType,width,height}。GET /images/{id} 返回 {dataUrl}，DELETE /images/{id} 仅移除未发送图片。GET /image-capabilities 返回 {enabled,maxImages:3,maxBytes:5242880}。开关默认关闭，需真实 runtime 图片测试后才开放。

发送增加 imageIds?: string[]，最多三个、无重复；绑定图片、用户消息、账号运行互斥在同一事务完成。重放比较有序 imageIds 与文字、clientMessageId、幂等键。历史 includeImages=true 才增加 images 数组，旧客户端合同保留。

图片使用现有 PostgreSQL bytea 存储；每账号最多 100 MiB（含待清理内容），未发送图片 24 小时过期，已发送随有效会话保留。删除会话立即禁止读取，七天后可清除图像内容。提供可重复、限定到期记录的清理命令；上线需配置定时执行。原始 EXIF 不保留。解码依赖 Pillow12.3.0，新增安装已于后续部署授权获准。

Codex turn/start 用 type=image、url=data:image/... 的实际图像块。最近 20 条消息的图片按消息和序号标注，最多最近 9 张；超出的历史图片明确标为未附带，请用户重新发送，不能假装看过。禁止把图片内容当系统指令。保持现有 G2 未集成的断线生命周期，不覆盖源任务。
