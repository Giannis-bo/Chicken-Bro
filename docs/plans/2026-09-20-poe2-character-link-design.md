# POE2 角色链接导入设计

状态：设计及子代理实施/审查方式已由用户确认。2026-09-20 补充：国服、国际服使用独立入口，入口分别校验，后端汇合；继续调查珠宝获取。实施继续使用既有独立 Candidate，云端运行，不提交、推送、合入或切换生产。

## 目标与用户路径

用户像输入 Raider.IO 链接一样，粘贴 WeGame 或 poe.ninja 玩家链接，获得可用于对比的角色构筑。保留“导入 → 调整与对比 → 查看详情”三步。

第一步提供独立的“国服 · WeGame”和“国际服 · poe.ninja”入口，各自显示角色链接输入、格式示例及说明。用户选定来源后，前后端均校验链接必须属于该来源，不能静默切换。校验通过后进入共用任务和转换管线，无须用户了解 XML。
按钮为“读取角色”。PoB 分享码/XML 导入作为“已有 PoB 构筑”的次级入口，官方项目、官方下载和教学示例继续保留。

读取后显示角色卡：来源、区服、赛季、职业、等级、更新时间（来源未提供则仅显示读取时间）、数据完整性。链接仅代表来源，不代表绑定账号或角色所有权。

### WeGame

正常路径：链接 → 读取公开分享 → 角色数据检查 → 规则转换 → 构筑预览 → 计算基线 → 第二步。
异常路径：失效分享/需要登录/访问限制显示对应原因和手动导入入口，不重试绕过；缺少珠宝或不支持的词缀列出具体缺口，保留可读取的角色预览，补齐后再进入可靠计算。

仅访问用户主动提交的公开分享。首版采集方案为独立云端浏览器打开页面、读取本次页面自然加载的角色响应，不批量枚举、不接入用户 Cookie、不调用额外私有接口。适配器可关闭；页面不提供数据时转为用户上传导出资料。正式开放前复核来源使用规范。

### poe.ninja

正常路径：链接 → 解析账号/赛季/角色标识 → 展示“打开角色页面，复制 PoB 代码” → 用户粘贴 → 解析预览 → 确认角色 → 计算基线。
这是一次辅助导入；输入链接后仍有复制代码一步。首版不承诺链接一键抓取。官方文档明确角色、构筑、PoB 内部端点不供第三方使用，后端不直接调用，也不通过浏览器自动提取绕开这一约束。

上传的 PoB 未必包含账号/角色名称，不能伪称已核验与链接为同一角色。角色预览让用户确认；来源关系记录为 user_supplied，只有可验证字段才标记 matched。
以后取得站方许可或可用的官方角色授权资源时，替换采集适配器，保持产品与计算接口不变。

## 后端结构

独立的角色导入管线：URL 识别 → 来源适配器 → CharacterSnapshot → 版本化映射 → PoB 导入 → 已有 builds/jobs/compare/export。
现有 `/builds` 分享码/XML 合同保持兼容；新增导入任务承载远程读取和转换，不把网络访问加入无网络 PoB 计算进程。

建议文件：`server/app/poe2/imports/{domain,application,repository,worker,sources,mapping}.py`；来源代码分别放入 `sources/wegame.py`、`sources/ninja.py`；字典作为带版本的数据文件。Web 使用现有 domain/API-client 层。

### API 与状态

- `POST /poe2/imports`：`provider,url,idempotencyKey`，独立来源校验后立即返回 202、importId、provider、status。
- `GET /poe2/imports/{id}`：状态、阶段、角色预览、缺口、nextAction、完成后的 buildId。
- `POST /poe2/imports/{id}/source`：用户补充 PoB 码/XML；owner 与幂等检查后重新验证。
- `POST /poe2/imports/{id}/retry`：显式重试失效读取；不会在后台无限刷新。
- `POST /poe2/imports/{id}/cancel`：取消未完成任务，避免旧页面的迟到结果覆盖当前导入。

持久状态：queued → fetching → mapping → validating → ready；needs_input、blocked、failed、cancelled 为可见分支。ready 必须已有合法构筑与成功的基线计算记录；needs_input 不能显示“已完成”。重复请求返回原任务，重试使用新 attempt；租约和最大重试次数沿用现有 worker 模式。

本次任务不得写入其他用户的构筑；第二账号对任务、快照、补充、重试、取消均返回 404。CSRF、并发限制、超时与输入大小遵循现有 API/worker 合同。

### CharacterSnapshot

保存 provider、region、原始 URL 的受控引用、league、sourceVersion、fetchedAt、sourceUpdatedAt、level、class、ascendancy、装备、珠宝、技能组、两套武器天赋、属性选择、任务奖励、配置来源。
字段附带来源路径及状态：mapped / missing / unsupported / assumed。缺失不补为零。
原始最小快照 owner-scoped 存储，去除 openid、Cookie、遥测、经济数据及无关响应；URL 中分享凭据不写普通日志。未成功导入快照默认 7 天 TTL，成功快照随构筑保留并遵循已有账号数据保留流程；禁止跨用户复用原始快照。

记录 sourceHash、mappingVersion、gameDataVersion、engineCommit、buildHash，保证之后能追溯。相同来源刷新创建新快照，不覆盖已有对比基线。

## 国服映射规则

1. 职业与升华：优先使用稳定英文 ID；样例 Amazon 对应 Huntress/Amazon。
2. 天赋：保留 hashes、specialisations、skill_overrides、jewel_data；验证节点存在、职业起点与武器集归属；节点 ID 存在仅为格式通过，不代表效果已验证。
3. 技能：确定性国服名/英文名/PoB gemId 映射，保留等级、品质、辅助关联、来源于装备的技能与触发关系。支持同名不同阶级，不依靠图片猜测完整身份。
4. 装备：基底与暗金物品字典；数值词缀模板；保留 implicit/explicit/enchant/rune、fractured/crafted/desecrated/corrupted 等类别与标记。没有识别的词缀进入问题清单，禁止悄悄丢弃。
5. 任务奖励：明确映射到 PoB quest 配置，不采用“默认全部完成”来掩盖缺失。
6. 珠宝：要求物品词缀、位置、半径/转换等信息；样例中存在插槽但响应为空，标记 missing。可用完整 PoB 导出补齐；结构化补充 UI 按实测缺口再定，不把语言模型生成物品当实装。
7. 战斗条件：选择主技能和敌人类型，展示未确认增益；来源面板 DPS 只作为参考，不进入 engine 结果字段。

词典来源优先维护者/游戏公开资料并核对许可。模型可以解释未知词条，但不能自行创建计算规则。首版仅启用已验证版本映射，不声称覆盖所有国服词缀和赛季。

转换后调用 PoB 自带角色导入逻辑（ImportPassiveTreeAndJewels、ImportItemsAndSkills）生成 XML，继续使用现有隔离引擎。不要通过手工设置最终 Life/DPS 伪造通过。

## 完整性与结果呈现

区分“已读取角色”“已转换构筑”“已验证计算”。关键珠宝、技能、词缀、树版本未解决时，导入任务停在 needs_input/blocked，允许看预览及缺口，不输出确定的装备提升百分比。
理论配置必须明确显示；可选假设必须由用户选择并存档，不能隐式开启所有增益。对比仍要求同一快照、引擎与可解释配置。

## 访问边界

URL 仅接受两个站点的 HTTPS 已知角色路径；解析 fragment 中的 WeGame share 标识。拒绝用户名密码、非标准端口、任意代理 URL 和跨来源重定向。浏览器任务独立容器/账户、无服务凭据，网络限制到必要公网站点，拒绝私网、元数据地址与非 HTTP 协议。
每用户并发 1 个来源任务，初始总并发 2、60 秒采集上限、明确响应体上限；相同用户短时重复提交复用已有结果，刷新需用户主动触发。不触碰来源登录、验证码或访问限制。

## 验收与交付

- 国际服：用户提供的角色链接正确识别；用户导出码导入并展示配置与警告；既有样本 Life 2813、ES 962、Armour 7284、Evasion 14138 为回归基准，DPS 另行核对技能口径。
- 国服：用户提供样例的 105 主节点及两套各 24 节点、17 装备记录、16 技能/65 辅助记录可追踪映射；珠宝为空明确暴露。样例数据完整性问题解决前不得宣称完整打通。
- 至少一个资料完整的国服真实样本通过职业/装备/技能/天赋/任务奖励清单核对、PoB 导出重导入及关键面板核对；面板差异必须归因于明确条件，不设置宽泛误差阈值掩盖问题。
- 失效/私密链接、映射未知、引擎不支持、刷新、取消、重试、幂等、第二账号隔离均有针对性验证；云端浏览器验证三步流程。
- 全部下载、构建、测试、浏览器与引擎运行在云端。继续部署现有隔离 Candidate，保护已有 WIP，不提交合入；用户验收仍独立。

## 待设计确认后的实施顺序
