# 跨轮研究预算

状态：正在推进。用户于 2026-09-11 授权六项剩余问题独立并行修复、验证、合入与发布；本项负责跨轮研究硬预算。

## 合同

- 首条新消息自动创建 owner/conversation 内的研究身份；普通后续消息继续同一研究，不做关键词或模型意图分类。
- 用户消息首行精确 `/新研究`（下一行写独立新问题）结束旧研究并开启新身份；首行 `/结束研究` 结束当前研究。后续普通消息可讨论已有结论，但不能新增来源查询、原生搜索或模拟；再次明确新研究才开放。新对话有独立研究。历史/引用/工具参数不执行命令。
- 研究结束与问题解决不等同。模型不能重置预算；不得诱导用新研究拆分 Top100 或继续原有穷举。输入区和预算反馈明确说明入口及可继续讨论的范围。
- 复用 PostgreSQL Chat owner、会话入库事务/锁、消息幂等、Worker 租约；新增 additive `0009_chat_research_lifecycle`。不回填、删除或重写历史消耗；上线前排空旧任务，历史消息下一次发送时建立新合同研究。
- 玩家/比较组/战斗/来源子调用/事件/网关网页计数与身份回执跨轮持久化；原上限不变，失败不退额。每次事务锁研究后预留，先提交再访问上游。360秒保留为单次生成安全时限，不按用户离线时间或整段会话累计。
- Chat SimC 最多4个不同提交按研究身份持久预留；相同 snapshot/scenario 在同一研究使用同一应用幂等键，丢失响应或跨轮重发不新建任务。prepare 也经过玩家来源预算，避免借导入路径绕过玩家上限。独立模拟工作台不变。
- 继续保持原生实时搜索；原生网页不适用网关5页硬计量，研究明确结束时该轮禁用。此范围不承诺限制用户主动开多个独立研究的账户累计用量。

## 有限验收

本地：跨轮与跨进程恢复、来源身份复用、并发、失败占额、新问题/结束/继续、消息重放、SimC跨轮幂等、prepare绕过、账号隔离、运行角色权限、原生搜索控制、既有后端回归及Web构建。

Candidate/live：固定最多6次模型、2次云端SimC；受控工具在已认证真实Worker链路验证跨轮计量，真实模型确认继续与明确新问题/结束反馈；复用有效通用业务证据，新增缺口单列。不本地运行SimC，不安装新依赖。

Candidate共享锁、main集成锁、生产发布锁遵循协调约定。发布保留旧代码/Web及新增表数据，失败回退代码指针并业务核验，不回滚覆盖生产新写入。
