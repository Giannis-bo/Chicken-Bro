# Equipment Simulator Phase 2 Canonical Resolver Implementation Plan

> **Execution mode:** Continue the active Goal. Use Repo-native Harness v0.5, TDD, local CR, exact-PR-head candidate deployment, GitHub CI, post-merge live smoke, and evidence archiving. Do not delegate or spawn subagents.

**Goal:** Implement the canonical pure gear Resolver, typed Evidence Ledger v1, bounded PostgreSQL Authority Context loader, and a dormant `websim_payload.py` compatibility facade with golden parity, without activating a resolve route or moving any frontend/runtime consumer.

**Architecture:** Two separately reviewable Strict slices. Slice 2A adds only pure resolver/evidence modules and deterministic fixtures. Slice 2B adds the PostgreSQL-only read adapter, bounded cache/query budget, and a dormant serializer compatibility facade. The Resolver never accepts a database handle; the loader owns one read-only transaction and at most three cold domain queries. Phase 2 creates no formal Active Season Manifest: it exposes an explicitly transitional `compatibility-pg-live-v1` authority manifest derived from current PG state plus server-owned runtime revisions. Phase 4 remains the only owner of immutable releases and the active retail Manifest.

**Tech Stack:** Python 3 `dataclasses`, `TypedDict`, `hashlib`, canonical JSON, `unittest`; PostgreSQL/psycopg through the existing `PostgresCacheStore`; Repo-native Harness v0.5; GitHub PRs; known Lighthouse candidate deployment.

### Exact query budget

1. `AUTHORITY_REVISION_SQL`
   - reads `gearCatalog` and `websim_sync` sync states;
   - returns current season plus a deterministic compatibility catalog fingerprint from counts/max-updated identities of items, variants, options and sources.
2. `SELECTED_ITEM_VARIANT_SQL`
   - one CTE/array query for all selected `(itemId, variantKey)` pairs;
   - returns item, verified variant, authoritative source/evidence and canonical item-set facts.
3. `SELECTED_OPTION_SQL`
   - one array query for all selected option IDs/variant IDs;
   - returns visible verified gem/enchant/runeforge/embellishment/crafted/Catalyst facts.

Transaction-control operations are recorded separately; cold domain `SELECT` count must be exactly three for both 1-slot and 16-slot intents. Warm cache hit may execute query 1 only to bind the current full Dependency Vector.
