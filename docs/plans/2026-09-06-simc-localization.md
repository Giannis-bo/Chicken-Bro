状态：正在推进。2026-09-06 用户已批准对话中的六部分方案，并授权实施。沿用 `.worktrees/simc-workbench` 与隔离测试发布范围。

**Goal:** 按游戏身份与版本统一解析技能、增益、召唤物、装备触发名称，替代按职业补全前端词表。
**Architecture:** 原始报告保留标识与统计层级，服务端使用版本化 zhCN 数据包生成独立名称投影，两端消费同一投影；不改变统计结果。
**Tech Stack:** 当前 Python 服务、Taro/TypeScript 客户端、云端受管 SimC；不新增运行期外部查询或数据库。
**Spec:** 本计划的已批准合同，来自本任务用户确认的方案；不另外创建方法层权威文档。
**Method:** 使用 writing-plans 与 TDD，按下列步骤顺序实施；需要执行方法时使用 executing-plans。

## 已批准合同

- 名称数据必须有实际可验证的版本来源。当前网站查询抓取日期不是游戏构建版本；禁止把最新数据伪装为历史版本数据。
- 保留技能 id、内部名称、报告名称、物品编号、来源身份和父子结构。单行合计不得按子项再求和，也不得从多个候选中任意选一个名字。
- 普通游戏效果按法术编号解析；召唤物来源使用 NPC 身份；少量模拟器内部项使用版本绑定的明确语义规则。
- 解析状态区分已核实、歧义、缺项和历史身份不足。显示中文，不猜译，不用“其他”掩盖缺项。
- 网页/小程序统一消费服务端投影；旧客户端继续收到旧合同。旧存档不写回、不改变数值。
- 新引擎/数据包发布前执行当前支持专精、配置、宠物及装备效果矩阵；未覆盖项如实报告，不承诺尚未验收的职业。
- 不本地安装或运行 SimC；新依赖须显式授权；不切生产、不合入 main、不进行历史批量回填或数据清理。
