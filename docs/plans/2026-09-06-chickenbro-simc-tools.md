# 鸡哥按需调用云端 SimC

状态：正在推进。2026-09-06 用户明确要求参考已验收的研究工具方式，将 SimC 按需接入鸡哥；本计划记录该执行授权。

## 正常与异常路径

鸡哥理解模拟请求后准备当前账号拥有的角色快照，展示/说明使用的角色和场景，调用正式 SimulationApplication 提交任务；查询进度与语义结果，结果与现有 Mini/Web SimC 列表共享。用户已经要求执行时不再机械要求确认。只讨论/解释时不自动跑任务。输入缺失报告真实 blocker，不猜等级/装备/天赋，也不把 API 未接入和输入不完整混淆。

范围包括单次模拟及图2所需的同快照宝石对照、固定时长/目标数、结果误差说明。只用现有云端 runtime、PostgreSQL queue 和 Worker，不新建平行任务系统，不安装或本地运行 SimC，不接入旧 simulator API。

## 实施

1. 源与可执行输入核验：检查真实 Raider.IO 快照，补齐可以从可信公开来源核对的缺字段；无法核实则保留 blocker。验证现有云端增强专精能力，不能仅改配置冒充 runtime 通过。
2. 场景/compiler：有界时长和宝石槽位替换，保留快照与原天赋装备；场景哈希涵盖全部变更。旧请求语义和既存任务可读；结果保留真实误差与 provenance。
3. Chat 工具：按服务器 Principal/会话/run 绑定短期 capability，模型不传身份；prepare/submit/get/list 经 application，幂等提交、有界任务数与轮询、结束撤销。跨用户 ID 不可读写。
4. MCP 与规则：暴露按需工具，解释/准备不冒充执行、排队不冒充结果、个人对照结论遵循差值与误差。通用工具优先，不为增强萨硬编码答案。
5. 验证：隔离工作树、针对回归、云端既有依赖的全后端/控制面、独立代码审查；测试 release 保留回滚，真实 Astra 发起任务、云端 SimC 完成、同账号列表/结果核对。正式切换和用户验收单独记录。

## 已知基线

基于已验收研究分支 a1201c15；原工作区保持3be4e6cb。本轮开始时 Drakthul 真实来源返回 CHARACTER_LEVEL_MISSING 和 RUNTIME_UNAVAILABLE；必须调查这些限制，不能仅新增工具名称后宣称可用。
