# 通用阶段状态模拟实施计划

> 执行方式：本会话按测试、实现、验证顺序逐项执行。用户已授权直接实施、Giannis 验证后先汇报结论再发布。

**目标：** 支持跨职业初始资源/Buff/普通冷却、固定阶段窗口及逐迭代证据。
**架构：** 编译器 v7 将结构化条件编译为原生 SimC 参数；云端 Port 执行状态发现和有界单迭代批次，Worker 验证并持久化聚合；Chat 暴露条件、结果和限制。沿用 owner、队列、幂等与来源合同。
**技术：** Python 标准库、现有 FastAPI/PostgreSQL、现有云端 SimC，无新依赖。
**方案：** [可行性试验](../../artifacts/verification/2026-09-20-phase-state-probe/README.md)。

## 约束与重点

- SimC 仅云端运行；保留旧编译版本任务及全部 WIP。
- max 需按角色引擎上限解析，不能固定职业常量；首次动作不能代替初始快照。
- 不存在或未观察到的状态失败；状态层数/时长不匹配失败；原生覆盖机制警告保留。
- 相同时间的动作按报告事件序号展示，增益携带与实际增伤区分。
- 每迭代单独统计，禁止用一个抽样序列声称全迭代覆盖率。
- A/B 控制条件一致，药水暴击须验证实际效果；不得仅修改 B 的角色属性。
