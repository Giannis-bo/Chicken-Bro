# 装备模拟校验状态卡移除设计

## 背景与用户体验

玩家在“职业专精查询 > 装备模拟”中选择装备时，页面顶部当前会展示一张全局装备校验状态卡。它会显示校验状态、配置签名和问题列表，例如“当前装备配置未通过校验”。这些属于内部处理过程，不应在用户浏览和选择装备时被显式展示。

本次交付后，玩家将直接看到装备选择和属性内容；无论装备状态为等待、校验中、已校验、阻断、离线或数据版本冲突，页面顶部均不展示这张状态卡。需要阻止保存、编辑或进入 SimC 时，仍在对应的操作处维持既有禁用与提示，避免把未校验配置用于后续动作。

## 方案与边界

采用最小展示层收敛：从 `pages/builds/detail.wxml` 移除整个 `gear-workbench-status` 渲染块，包括状态文本、配置签名和问题列表。

不改变以下内容：

- 前端 workbench 状态、服务端 Resolve 校验、已验证快照和 fail-closed 保护；
- 保存模板、编辑强化、进入 SimC 等操作的可用性判定与按操作反馈；
- `gearDataWarningText` 代表的装备数据接口可用性提示；它不属于被移除的 workbench 状态卡；
- API、后端、定时任务、health/admin、数据库和部署行为。

不采用仅隐藏 `blocked` 状态的方案，因为用户已明确整块状态都不应展示；也不删除内部状态字段或校验分支，因为这会扩大风险并削弱动作保护。

## 实现边界

- 删除 WXML 中的全局状态卡节点，不保留空白占位。
- 保留 JavaScript 中的状态派生字段，供既有动作保护和测试使用，不将其重新绑定到该页面位置。
- 更新页面结构测试：断言状态卡的三个展示绑定不再存在，同时保留操作禁用条件的覆盖。

## 验收与验证

1. 进入装备模拟页时，不显示全局装备校验状态、配置签名或问题列表。
2. 在等待、校验中、已校验、阻断、离线等任一状态下，上述区域均不出现。
3. 未通过校验时，保存、编辑强化和进入 SimC 的既有保护仍然生效。
4. 运行针对页面的 Node 测试、WXML/JS 语法检查和 `git diff --check`。

## 风险与回滚

风险限于少量页面可见性变化；不触达运行时协议或数据写入。若需要恢复全局状态展示，可还原该单个 WXML 渲染块，而无需改变服务端状态或校验逻辑。
