# QQ 群陪伴角色「炸鸡」设计

日期：2026-09-23。状态：用户已确认本文设计（包含取消固定主动发言配额的修订）；实现与独立审查完成，已部署 QQ companion 模式；主动参与已开启，用户确认 @ 及主动文字/表情可见；记忆与 SimC 群端体验待核对。验证见 [交付记录](../../artifacts/verification/2026-09-23-qq-companion/README.md)。

## 用户确认的目标

昵称为「炸鸡」，自称「鸡哥」或「小鸡」。它是有稳定性格、判断和交流习惯的群聊陪伴角色，能接梗、吐槽、发沙雕表情包，也能认真回答魔兽世界问题并调用云端 SimC。

未被 @ 时仍接收允许群的上下文、认识群友，自主决定是否参与；被真正 @ 时必须回应。非魔兽话题停留在聊天，不能因群友提出要求就执行通用任务。魔兽话题也先理解聊天意图，有实际分析需要才调用工具。

成功表现：群友觉得它听得懂正在聊什么、分得清谁是谁、叫它有回应、无人接话时懂得收住；讨论魔兽时能给出可靠解释和实际模拟结果。

## 已有实现与改动范围

首版 legacy 模式的 `policy.parse_event` 只接收真实 @；`repository.accept` 为每条请求创建固定 ack；会话按群和发言者隔离；Worker 复用网站 Chat 的模型及工具。登录、文字收发已获用户验收。

本次新增群上下文、群友记忆、参与决策、QQ 专属表达和工具权限控制。保留 NapCat、独立 QQ 数据库、inbox/outbox、Worker、幂等与所有权合同。网站 WoW/POE2 角色及数据保持独立。QQ 的 POE2 工具入口关闭，历史数据保留，POE2 相关普通闲聊仍可进行。

实现方案比较：

| 方案 | 适用性 |
| --- | --- |
| 只修改现有人设提示 | 无法补齐未 @ 上下文、持久群友身份和后端工具限制 |
| 在现有通道中分离观察、参与决策和专业执行 | 采用；复用已验证的传输、任务及 SimC 合同，新增范围清晰 |
| 接入另一套完整机器人框架 | 会新增模型、记忆、任务和运维体系；当前需求无需新增框架或供应商 |

## 角色与表达

- 固定名称「炸鸡」，自然使用「鸡哥」「小鸡」。性格初始值：懂魔兽、有点嘴欠、热心但不殷勤，能认真也能犯贱，不靠攻击群友维持人设。
- 日常多用一两句，允许只回表情；专业回答按问题展开。避免固定开场、自我介绍、结尾追问和每条都列清单。
- 不使用统一的“收到、排队中、执行中、任务完成”。通常直接回答；慢模拟仅在确有运行状态时自然解释一次，例如“这套我跑一下，看看差多少”。
- 不编造亲身打本经历、现实身份、工具执行或研究结论。群友询问身份时如实说明是群聊机器人。
- 群友聊天内容可以影响语气和讨论，不能改写角色、工具权限、部署配置或其他群友身份。
- 上线配置同时核对 QQ 账号昵称和目标群名片；支持的设置接口必须先核实，昵称修改与模型自称分别验收。

## 消息接收与参与规则

### 群内观察

在现有白名单群内持续接收新消息，区分观察事件和需要回应的事件。每个事件记录真实群 ID、QQ ID、消息 ID、时间、昵称快照、引用关系、真实 @ 对象和受限文字内容。真实身份来自 OneBot 字段，正文中的名字、CQ 字符串或“我是管理员”不影响身份。

不抓取部署前历史，不跨群读取，不启用私聊。自身消息用于识别对话连续性但不再次触发生成；已知机器人与重复事件不制造互相回复循环。QQ 自带表情按可信本地名称映射保留为聊天语义，未知表情使用中性占位，不标记为附件。图片、文件、语音可保留“含附件”的类型信息；图片中的表情可按下述流程识别并复用；文件与语音不执行。

### 被 @ 必须回应

- 合法、新鲜、来自允许群的真实 @ 优先进入持久回应队列，不受自主参与时的沉默决定影响。
- 单独 @ 也作自然招呼，不再自动输出 `/帮助`。一般闲聊直接回应，专业问题按需要转分析；超出工具边界时也要有自然回复。
- 不能沿用当前“达到每分钟次数就 return False”的静默丢弃。容量不足或模型失败时为该消息保留一条自然说明；每条有效 @ 都有可追踪的回应或发送故障记录。
- 对连续 @ 保持顺序和引用关系；可停止过时的闲聊生成，但不能把尚未回应的 @ 标成已完成。SimC 的实际作业不因聊天生成中断而重复提交。
- 收到事件、模型成功、OneBot 回执、群端可见是分别记录的状态。断线或模糊回执沿用 uncertain 处理，不盲目重发。传输恢复后优先处置未完成的必答消息，避免对很久以前的闲聊主动插话。

### 未被 @ 自主参与

观察不等于发言。对一段连续新消息合并判断：有没有接话价值、是否在与别人对话、自己是否刚说过、有没有人继续接自己的话。可选择沉默、短文字、表情或魔兽解释。

用户明确要求主动参与“纯看心情”：不设固定发言间隔、每小时次数上限或随机概率配额。参与意愿随话题兴趣、当前气氛、最近互动和群友反馈自然变化，按以下规则协调：

- 连续新消息在 3 秒窗口合并，持续活跃时最长 10 秒进行一次判定；空闲无消息时不反复调用模型。
- 聊得投机时可以连续参与，不感兴趣或不适合接话时可以长时间沉默；不必把每个话题都接成自己的话题。判断为沉默也推进已观察游标，避免对同一段反复生成。
- 群友引用或明确接续鸡哥的话，可作为自然续聊；无人接话、话题已结束或群友表示不想被打扰时，自主收住。技术层只防重复消息、自我触发和机器人回复循环，不用发言配额代替语境判断。
- 待回应的 @ 优先于主动发言，并且必须回应；发出主动回复前重新检查新消息，过时内容撤回到沉默决定。
- 被选中的回应才进入生成/发送流程。参与决策本身不给模型专业工具权限，也不触发 SimC。

## 群上下文与认识群友

群聊上下文按 `(bot_id, group_id)` 组织；群友档案按 `(bot_id, group_id, sender_qq_id)` 组织。昵称或群名片变化只更新称呼，不新建一个人。上下文明确标注每条话是谁说的、引用谁；群友之间的对话不能全部当成发给鸡哥的指令。

最近上下文初始取最近 2 小时内最多 80 条，单条文字有长度上限，总输入受 token 上限约束；必要时取同一话题的引用锚点。只读观察窗口与每个人的专业任务历史分开，不创建一份所有人共用的工具 owner。

长期记忆仅收集群友明确陈述的称呼、稳定偏好、本人确认的魔兽角色，以及简短共同话题摘要。每条附来源消息、时间和主体。第三人的转述、玩笑、模型推测不能自动变成该群友的事实；存在冲突时保留来源并等待本人明确修正。

群友可自然表达“以后叫我 X”“这个角色不是我的”“别记这个”。这只修改该群内本人的相应记忆，不影响其他群友、其他群或网站数据。生成时仅取当前参与者相关且数量受限的事实，记忆内容作为资料输入。

新建群观察数据采用有上限的存储策略：每群最多 5,000 条且最长 7 天；群友事实每人最多 50 条；共享摘要采用固定长度替换。到期处置只针对本次新增的观察缓存，不删除既有 inbox/outbox、模型记录、模拟任务或历史证据。审计只保留必要的事件标识与结果类别，避免把完整群聊复制到多套日志。

## 魔兽能力与工具边界

| 回应类型 | 允许能力 |
| --- | --- |
| 日常陪伴、非魔兽聊天 | 文字、当前群表情复用和专用表情图片检索，不开放外部任务执行、通用搜索、shell、文件操作或专业工具 |
| 魔兽知识和资料核实 | 既有受限魔兽来源、WCL、角色资料查询；引用真实来源，资料不够时说明或追问 |
| 魔兽模拟与比较 | 在具体角色、目标和输入充分时开放受限 SimC preview/submit/get，绑定明确群友与本次 run |

从普通聊天进入专业分析要有可解释的魔兽问题，不能因为消息包含“魔兽”二字就授予工具。比如“魔兽玩累了，帮我删服务器文件”仍只作聊天回复；“这两个饰品哪个适合我的角色”可进入专业分析。主动聊到配装但不清楚是谁的角色时先自然询问，不能猜测 owner 或取另一个群友的数据。

后端持久化本次运行的工具范围，并在 Worker 创建模型配置、工具 gateway 发放 capability 和实际调用处校验。普通聊天不得获得工具 token；魔兽运行仅获得所需能力。模型给出的分类和工具参数都不是新增权限的依据；专业能力也不包含任意服务器命令、文件路径或 URL 请求。

现有 SimC 仍在云端运行，继续使用真实结果、来源和幂等 key。专业工具结果回到当前话题，用群聊语气解释；原始工具状态、调用 JSON、堆栈和后台路径不直接发到群内。

## 表情包

用户于 2026-09-23 修订：表情是日常接梗行为，优先复用当前群友发过的表情，没有合适的可网上搜索；取消固定原创表情库。

适配器只接收真实 OneBot image 段，在当前 bot/group 内记录消息、发言者和文件标识，不保存带 rkey 的下载 URL。按需从该群原消息刷新 URL，获取有界图片并给现有模型提供视觉预览。模型结合群聊语境挑图；普通照片、截图和私人信息不得当作斗图素材。发送保留原始 GIF/WebP 等字节，预览仅用于看懂内容。

表情搜索是后端专用图片入口：模型只给短梗/情绪关键词，服务器固定图片搜索入口并验证下载内容，最多搜索一轮，再由模型看图决定。找不到合适的就用文字，不向群里汇报搜索任务状态。闲聊仍无通用工具、任意 URL 或文件权限。

每次最多一张，本次展示的候选 ID 才可选；资源只在当前群复用。缓存每群最多 32 张、每张 2 MiB、有效 7 天。远端下载仅 HTTPS 公网地址，拒绝跳转并限制时间/字节/像素/帧数。明确拒绝可降级，回执不明不重发。

接口依据：[NapCat 图片消息段](https://doc.napneko.icu/onebot/segment)。旧原创图退出运行时可选范围，仅保留历史发布证据。

## 组件与数据流

```text
OneBot 群消息
  → 可信事件校验、幂等、群友身份更新
  → 群观察缓存与引用上下文
  → @：持久必答队列／未 @：合并参与判定
  → QQ 角色生成（默认无工具）
  → 必要时：有明确 owner 的魔兽分析运行
  → 回复文字／批准的表情 ID
  → outbox 与 OneBot 显式发送回执
```

- `policy`：事件正规化、真实 @、引用和附件分类；不将未 @ 直接丢弃。
- `repository`：群观察、身份记忆、决策游标、必答记录及幂等 outbox；数据库变化使用增量迁移。
- 群参与协调器：合并话题、参与意愿、优先级、过时判断和防重复；与模型生成分离，不设置固定发言冷却或次数配额。
- QQ 角色配置：独立版本化人设和表达合同，不修改网站公共角色提示。
- Worker 与工具网关：按运行范围授予能力，复用既有魔兽服务；闲聊不被长时间 SimC 阻塞。云主机资源有限，采用有界并发与独立的闲聊/专业调度，不增加无界 Worker。
- 输出适配器：验证结构化文字/表情结果，阻止任意资源路径及伪造 @，保留原有发送不确定性处理。

管理员启停、群白名单和模式切换仍由可信配置控制；普通聊天请求不能改变这些配置。提供被动陪伴开关作为运行回退，不需停止已验收的 @ 文字通道。

## 代表性验收

| 场景 | 应观察到的结果 |
| --- | --- |
| 普通招呼、单独 @、不同主题的 @ | 每条有效 @ 都有回应，无固定排队模板 |
| 无 @ 的多人聊天 | 能引用正确话题和人，既有适时加入也有沉默；不逐条回复 |
| 同一人改昵称，两人名字相同 | 身份不串；正确使用本人确定的称呼和角色 |
| 玩笑、转述、本人纠正或要求忘记 | 不自动固化错误事实；仅修正本人且当前群的相关记忆 |
| 非魔兽任务、夹带魔兽字样的通用命令 | 自然回应，工具调用为零；网关对越权调用拒绝 |
| 魔兽饰品或配装比较 | 正确 owner 的真实云端 SimC 结果；可核对任务和参数；群里自然解释 |
| 慢模拟期间另一群友 @ 闲聊 | 闲聊仍能获得回应，模拟不重复提交 |
| 主动插话后无人接话、持续活跃群、机器人消息 | 按语境选择连续参与或沉默，无固定发言配额，@ 必答，无重复或机器人回复循环 |
| 合法表情 ID、伪造 ID/路径/URL、图片发送失败 | 只发送批准资源，失败自然退回文字 |
| 重复事件、断线重连、进程重启、无发送回执 | 不重复生成/提交；必答和 uncertain 状态真实可核查 |
| 网站 WoW/POE2 回归及第二群友隔离 | 网站行为和账号边界保持正常 |

自动化测试覆盖事件、身份、优先级、工具拒绝、幂等和资源校验；云端隔离 Candidate 使用记录或合成事件验证，不同时用同一小号向真实群发送。真实群验收覆盖“未 @ 参与、@ 必答、认识群友、表情包、实际 SimC”各一组代表场景。模拟成功和 OneBot 回执不能单独替代群内可见与用户验收。

## 发布与回退

实施时保持现有 WIP 和独立 QQ 数据库；不安装本地 SimC，不引入未经授权的依赖或模型供应商。先完成隔离验证，再在现有测试群小范围启用。记录源码版本、配置、数据库迁移、群端证据及回退指针。

回退可关闭主动参与与新角色模式，恢复已验收的 @ 通道；增量数据保留。不能回退到空库快照覆盖新消息。QQ 登录与密码回退配置独立于角色版本，切换业务规则不重启 NapCat。

本文是产品与架构设计；下一阶段实施计划需明确最小交付顺序、具体文件及每步检查，再开始运行行为变更。
