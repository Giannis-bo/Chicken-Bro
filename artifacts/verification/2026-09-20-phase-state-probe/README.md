## 推荐的通用技术方案

### 1. 结构化阶段合同

在已有 scenario 增加 `initialState`、`measurement`、`assertions`，复用现有 `actionLists`。资源用引擎资源标识，Buff 用已解析的 spell ID + engine token，冷却用已验证动作标识；中文名字仅作为检索入口。场景中不写职业/首领/药水名称分支。

- `initialState.resources`：绝对值或 max，禁止负值；max 由当前角色的引擎上限解析并在读回中验证。试验中的 1000 仅用于观察钳制语义，不作为产品魔法常量。
- `initialState.buffs`：层数与剩余秒数；不开放任意效果 value 改写。校验对象存在、层数上限、当前天赋/装备来源、允许预设标记。
- `initialState.cooldowns`：剩余秒数。首版只支持已验证的普通冷却；充能、多段恢复和隐藏职业状态需独立能力说明。
- `measurement`：固定时长、目标数、统计起点。首版采用“指定状态即 0 秒”，避免预备动作消耗初始 Buff 或混入伤害；完整战斗中的条件窗口单独扩展。
- `assertions`：声明初始资源/Buff、开场动作顺序、药水实际增益、动作携带 Buff、资源浪费等预期，结果返回 satisfied / violated / unsupported 及证据。

Buff 剩余时间是场景必要信息；若用户未提供，可显式采用“完整持续时间”的实验假设，不能默默猜测。初始技能冷却、目标减益、宠物及持续伤害状态同理。

### 2. 复用原生引擎能力

编译至以下已实跑接口，无需先改引擎：

```ini
initial_resource=maelstrom=125
override.precombat_state=buff.flowing_elements.stack=2
override.precombat_state=buff.flowing_elements.remains=15
override.precombat_state=cooldown.ascendance=10
```

云端 `engine/player/player.cpp` 的 `parse_initial_resource`、`add_precombat_buff_state`、`add_precombat_cooldown_state` 提供实现。预设 Buff 通过原对象执行，具有触发回调的能力；不是在报告中伪造一个 Buff 标签。引擎明确提示此功能可能无法正确恢复所有 Buff/冷却，因此需要下面的能力和语义验证层。

### 3. 能力发现与语义验证

以引擎二进制哈希、数据版本、角色配置和状态合同为缓存键，解析资源/Buff/动作目录，先做廉价单迭代预检。通用校验检查起始实际状态、层数变化、到期/消耗和失败原因。具有隐藏计数器、异步层数寿命、宠物快照、RPPM 历史的效果，不能仅靠一个 Buff 层数恢复；标记 unsupported，或转入真实准备阶段后再统计窗口。

通用是“状态模型、编译器和证据检查可复用”，不等于所有游戏状态均能任意注入。必要的引擎对象适配按机制登记和复用，不按聊天问题或角色名称硬编码。

### 4. 证据与多迭代统计

引擎 JSON 的动作序列已经包含 Buff 层数、当前及最大资源，当前应用的 `extract_action_evidence` 只投影时间/技能，需扩展。`gains` 已包含资源 actual/overflow，固定 20 秒场景可直接聚合；任意战斗子窗口则需要时间化事件。

首个动作快照不一定是 0 秒状态（盗贼样例即如此），同时间戳也不保证执行顺序。应保留事件序号并用日志/结构化事件核验动作执行与 Buff 消耗；区分施法时携带、实际消耗、伤害结算时生效。

单个报告的 sampled action sequence 只能证明一个迭代，不能宣传为全部迭代覆盖率。首版可用有界的单迭代分种子批次逐次计算，再聚合均值、分布和不确定性；规模扩大再增加引擎结构化事件/聚合输出，避免大量 debug 日志。每个迭代统计总伤害、指定技能施法次数、满足 Buff 条件次数、资源溢出及断言结果。

### 5. 比较实验

药水名称和使用时机通过现有 APL 表达；“鲁莽获得暴击”作为服药后状态断言。角色属性不满足时报告原因；若做属性调整，A/B 必须使用同样调整并明确实验假设。固定状态、装备、天赋、时间、嗜血与循环，仅改变待比较因素；相同种子可用于复现，不假设不同动作路径共享完全相同的随机事件。

优化循环属于另一个维度：有限候选循环先满足起手与状态条件，再按 20 秒总伤害比较，同时报告宗师覆盖与溢出。不能将一次可执行 APL 描述成已找到全局最优解。
