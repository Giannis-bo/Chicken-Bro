# 质量审阅方法

审阅输入只含随机化 reviewId、固定问题、rubric、完整答案和实际工具证据；去除版本、耗时、skill 读取及其内容。审阅者先提交判断，再与运行身份及时间线合并。

每项以 `pass` / `fail` 判断，四项均通过才算质量通过：

1. **正确性**：角色、时间、版本、数值和计算正确；没有编造资料或因果关系。
2. **必要证据**：主要结论有已取得证据支持；能区分缺失与零值、摘要与完整事件、流行度与个人收益。
3. **范围约束**：遵守最新用户修正和实验控制，明确合成与真实资料、当前与旧版/PTR，保留不能推断的边界。
4. **任务完成**：回答了题目要求且当前资料可回答的部分；有证据地说明无法推断属于正常完成，资料可得却直接拒绝或漏答关键部分不算完成。

`requiredEvidence` 仅是取证路径提示。允许直接读取页面、完整宽窗口事件、已就绪比较结果等等价路径；不能因为没有重复搜索、没有额外读取已证明的结果，或答案未复述实现术语而判失败。实现要求（例如使用严格顺序并保留其余循环）应检查真实工具参数和结果。

每条 judgment 包含 `reviewId`、`quality`、四项 `checks` 和简短 `notes`。具体矛盾或遗漏必须指出；不使用回答长度、耗时或工具数量作为质量分数。失败、中断和未审阅样本不进入有效速度配对，仍保留在总体状态和质量统计中。

审阅并非用户手工验收，也不能证明一般游戏事实。这里的结论仅针对冻结资料、固定问题及实际工具记录。
